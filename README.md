# 造书工作台

把一本教材 PDF，做成能交给 AI 老师上课的教学蓝本。你不用写代码，也不用懂 AI：
装好之后，在界面上点几下、把书传上去，它就一章一章把书写出来；每一处关键决定，
它都会停下来等你点头。

> 它在 dsh 的插件列表里叫 `dsh-craft-your-textbook`，装好后出现在「模式」下拉里，名字是造书模式。

成品是交给 AI 老师当授课底稿用的：AI 老师读它，再用提问的方式把一门课教下去。
你也可以在第 1 次拍板时选「自己也要读」，那样成品就是一本能直接读的教材。
它总是一个 Markdown 文件，名字就是你一开始定的书名（《初中数学·有理数》.md），
外加一份「这本书怎么用」的说明。

谁适合用：手上有教材、教师用书、考纲、讲义或真题，想把它整理成一门课的人——自己带孩子的家长、
备课的老师、做教研的老师。全程中文，不需要技术知识。想直接动手，跳到「安装」；想先弄清它怎么运转，
从下一节看起。

## 整件事里，只有五件事需要你出手

1. 上传材料——把 PDF 传上去。学生用书、教师用书、考纲、讲义、真题都行，一次能选多份。
2. 确认它读对了——它读完会给你一张「材料读完了」的卡：重点难点、建议分成几章、每章覆盖哪些知识点。你看一眼，对不对。
3. 拍板定方案——学习目标、教学方法、全书章节结构，分三次问你。满意就过，不满意就说哪里不对。
4. 确认章节安排——分几章、每章写什么，以及先拿哪一章当样板。
5. 抽查提意见——写的过程中你随时能翻某一章，直接在旁边写「这个例子太难」「多给几道练习」。

有一条规矩值得先说清楚：你没点头，它不会往下走。每一次拍板都会自动存档，
之后想反悔，可以退回上一个存档点重来。

## 装之前：先有 dsh，再备两把钥匙

造书工作台是 DeepSeek Harness（dsh）的一个插件，所以你得先有 dsh，并且能打开它的界面
（网页版、桌面版都行）。dsh 太老的话，插件装上去界面能开，但造书模式不会出现在模式下拉里
——看起来装好了，其实用不了。把 dsh 升到最新就行。

### 两把钥匙：模型接口 + MinerU Token

工作台本身不带 AI，也不带 PDF 解析，这两样要你自己接。第一把是大模型接口：在 dsh 里点右上角
设置 → 模型，添加你自己的模型接口，任何兼容 OpenAI 接口的都可以。这本书从读材料到写正文，
花的是这个接口的钱。

第二把是 MinerU Token：教材是 PDF，得先转成文字 AI 才读得懂，这一步用的是 MinerU。
去 <https://mineru.net> 注册，申请一个免费 Token，回到造书工作台里粘贴保存；忘了填也没关系，
点「开始转换」时它会提示你。

## 安装：粘一串，然后新开一个会话

### 在 dsh 的插件页面安装

1. 打开 dsh 的界面，点左侧边栏的插件（「新会话」下面那一项）。
2. 点添加插件，输入 **`dsh-craft-your-textbook`**，点安装。

装完不用重启 dsh：造书模式是插件包随包发出的一条声明，dsh 在运行时就会把它算进去，几秒内生效——
也正因为它只是条声明，硬盘上不用建模式目录，也不用复制任何文件。
只剩一件事要做：新开一个会话，已经开着的会话用的是它打开那一刻的模式，不会自己换。
不想点界面也行，命令行一样：`npx dsh-craft-your-textbook`，它自己会去查最新版。

装完怎么自查？新开一个会话，看输入框旁边那个「模式」下拉，列表里出现造书模式就是装好了
（列表里另外几个模式是 dsh 自带的）。

要是装到的不是最新版（刚发版的那一天容易这样），打开工作台它自己会提示有新版本，
照着它给的那一串装就行——不用回这一页来查版本号。

### 第一次打开：认一下门在哪

1. 打开 dsh 的界面，点新会话，在「模式」里选造书模式。
2. 中间会多出一个工作台页签——点进去，这儿就是造书的地方。

有个小地方会让人愣一下：造书会话里，你发出第一条消息之后，界面会自动切到「工作台」页签。
这是有意的，只切这一次；之后你手动切回「对话」，它就不会再打扰你。对话和工作台是两半：
工作台是流程卡，对话是你随时能问 AI 的地方，比如「这章为什么这么写？」「能不能把第 3 章拆开」，
直接在下面的输入框里问，不会打断它干活。

第一次用不确定怎么操作？建书那一屏上有一颗「先建一本演示书试试」，点它先看一遍全程：
不花模型额度，也不影响你自己那本真书。它演示的只是流程，幕后环节是占位，不会真产出内容，
你写给它的意见也不会被采纳。

## 升级

装完最常见的一个困惑是「明明出新的了，我怎么还是旧的」。dsh 装插件时会把当时那一版记在
你的配置里，之后就一直按那一行装，不会自己回头去看新的。插件页面上的「更新」按钮管不到它，
卸载再装一次也升不了级。想升级就跑这一条：

```
npx dsh-craft-your-textbook --upgrade
```

跑完不用重启，新开一个会话，看「模式」下拉里有没有造书模式。

如果它说「不认识的选项」，说明你硬盘上那份安装脚本是旧的：用插件页面上的「更新」按钮，
或者卸载后回「安装」那一节重新装一次。它不会自动更新——想升级就得自己跑上面那条命令。

## 造一本书：七步，每步你都在场

下面这七步就是完整流程。你不用记，做到哪一步，工作台上就摆着哪一步的卡；
这一节的作用是让你心里有数：现在走到哪儿了、接下来会发生什么。

### 第 1 步 · 上传材料

一个会话只造一本书。所以你一进工作台，如果这个会话还没有书，它直接把建档的表单摆在你面前，
不用先找什么「新建」按钮。填两样：书名（这就是最后下载的文件名），
和「想学完能做到什么」（一句话就行，比如「能自己算一元一次方程，并讲清为什么要这样算」）。
拿不准书名怎么起，点「✨ AI 建议」让它先拟几个，你再改。填好点创建这本书，上传区就出来了：
把教材 PDF 一次选好（可以多选），然后点开始转换。每份是什么材料（学生用书、教师用书、
考纲、讲义、真题），你不用在这一步标——下一步它自己判定，判完在卡上写给你看
「角色：教师用书（依据：……）」，你看着不对再说。

理科教材记得勾上「理科内容」：公式多的时候，要打开公式识别。

### 第 2 步 · 它读完，你确认

AI 会把每份材料通读一遍，整理出「源材料索引和知识地图」。读完，工作台弹一张
「🔍 材料读完了！」的卡，上面直接能看到重点难点和建议的章节安排；点开还能看知识点清单
（带难度），以及每份材料里读到了哪些小节。

看着对就点「✅ 满意，继续设计」；不对就点「🔁 让 AI 重做」，点完还会让你确认一次免得误触。
可以勾个理由，也可以只写一句「第三单元讲浅了」，什么都不填它也会重做。

确认之后还有一小步，很多人会漏：它会按材料拟出 3–5 条「学完能做到什么」，单独摆一张卡问你
「这几条学习目标可以定下来了吗？」。就按这几条，点「✅ 就按这几条办」；想改，点
「🔁 让 AI 重写这几条」，或者直接在列表里改、删、加。

### 第 3 步 · 三次拍板，再确认章节

接下来是三个设计方案，一个接一个来，每一个都要你点头：

| 第几次 | 要你定什么 |
| --- | --- |
| 第 1 次拍板 | 学习目标与难点——这本书学完要会什么、难在哪儿。这一屏还会问你「这本书主要怎么学」：自己也要读，还是只让 AI 老师带着学（决定成品是给你读的正文，还是给 AI 老师的教学蓝本）。选完即锁定 |
| 第 2 次拍板 | 教学方法与板块——每章里放什么板块、怎么讲 |
| 第 3 次拍板 | 全书架构与章节——分几章、每章讲什么 |

每次都是两颗键。满意点「✅ 通过，继续」；不满意点「❌ 驳回，提意见」，先选是「方案不对」还是
「我看不懂」，再点选理由（讲太深了 / 讲太浅了 / 不是我要的重点 / 和别的部分重复 / 换个风格），
不用打字。

第 3 次拍板之后还有一道章节安排确认：全书分几章、每章写什么，会列成一张表给你看。
这一屏上你还能改一件事——先拿哪一章当「最佳范例章」，AI 会建议一章，你可以从下拉里改选。
每章写多少字，要等范例章写完、实测之后才定得下来，所以那是下一步的事。满意点
「✅ 通过，开始写最佳范例章」；要调就点「🔁 让 AI 重做」，再写一句哪里要改。

### 第 4 步 · 先写一章给你看（最佳范例章）

AI 会先亲手写出一章，当全书的样板——这一章定下来，后面所有章都照它的样子写。
新稿默认整篇给你看原文；想看改在哪，点「和第 N 稿对比」，红删绿增一目了然，
看够了点「只看这一稿」回来接着读。读到不顺眼的地方，鼠标停在那一行会浮出三个键：
😕 这种写法不喜欢、🗑 这类内容不需要、✏️ 要改成……。😕 和 🗑 在同一处点两下就是撤销
刚才那条意见（✏️ 的撤销在意见单里）。

这一章要过三道小关，都在同一屏上：

1. 这一稿行不行——行就点「✅ 就用这一稿」，整章都不要就点「🔁 不满意，重写这一章」。
2. 各章多少字——定稿区有一份字数清单，按章列出每章多少字、为什么是这么多，你可以逐章改。
   改完点「💾 保存各章字数」，不用再敲一个统一字数。
3. 定稿——点「✅ 就按这章的风格写全书」，这一章就成了全书的样板，其余章节照它写。

### 第 5 步 · 写完整本，随时可以抽查

其余章节开始铺开写。工作台会出现「章节清单」，每一章你都可以展开读、点「打开」在右栏看，
或者点「✍️ 写意见」提一句，比如「例子太难，多给几道练习」。

你写的意见会当场转达给正在写那一章的人，不用等整章写完再打回；一章写完，得先把你提的意见
处理完，才轮得到你过目。

### 第 6 步 · 全章过目

全部章节写完后，AI 不会直接把书交给你，它会停在一张「全章过目」的卡上，等你逐章看完：
每章可以展开看、可以写意见，改了它会重新审一遍。全都满意了，点「✅ 都过了，进入最后检查」。
点下去之后，它不会马上合并，而是先把全书通读一遍，专挑那种「单看每章都对、连起来不对」的问题：
事实前后有没有打架、术语统一没有、交叉引用指得对不对、知识点是不是一节节往上走。

### 第 7 步 · 最后检查、你认可、下载

它会亲自把成品从头读一遍，需要的地方整体调一遍，再核四件事：内容追不追得回你的材料、
章名重不重、有没有乱码、章数和说好的一致不一致。全部过了以后，交付前还有最后一关：
「最后检查结果认可」卡。AI 的自查报告和核对结果都摆在你面前，这是你对整本书的最后一次把关。
满意点「✅ 认可，交付」；不满意就写一句意见，AI 会改整本、再重新检查一遍。

认可之后，交付卡上会出现一份「你的风格线条条有着落」——你在过程中提的每一条风格意见，
落在哪几章、或者为什么没用上，逐条列给你看。然后点「⬇️ 下载《书名》.md」。
下载到的文件名就是你当初定的书名，后面附一份「这本书怎么用」的说明：怎么交给 AI 老师、
怎么让它按这本书上课。

## 途中能用的两个按钮

定点修改：某个决定已经拍过板、流程也往下走了，你才想起来要改——不用从头再来。在那一步点
「✍️ 定点修改」，它会先弹一段影响预告：哪些下游要重做、哪些原样保留（你的风格线和你放行过的
检查都不动），改的过程中每一步仍然会请你拍板。改完 10 分钟内、而且这之后账面上没有新的进展，
可以一键撤销；超过这个窗口，就只能回退到存档点。

催办：AI 说「我记下来了」，但工作台迟迟没变化，或者它看起来停了——在对话里点
「⏰ 提醒 AI 记下来」（有些状态卡上是「🔁 让 AI 接着干」）。它会立刻去查账，
把答应了没做的事补上、把停下的活接上。

## 你的书放在哪，哪些东西别手改

建书的时候，工作台会在当前会话的工作区目录里给你建一个文件夹，文件夹名就是书名。你上传的
PDF 原件、转出来的文字稿、写出来的每一章和最后的成品，全都在这个文件夹里。文件夹里有一份
`README.md`，说明每个目录放什么（包括 `工作区/`）、哪些别手改，照它来；同名的第二本不会覆盖
第一本，会建成 `书名-2`。

左侧会话列表那一行会变成「造书 · 书名」，以后每次改名也跟着改；但硬盘上的文件夹名建书时
就定死了，改过书名之后两者可以不一样，这是正常的。工作区目录读不到的时候（很少见），
书会退到默认目录 `~/.dsh/textbook/projects/` 下面，老书如果还在那儿，照常能用。

每本书还有个内部编号（`book-xxx`），「编号 → 书文件夹在哪」记在 `~/.dsh/textbook/registry.json`
里。这些数据不跟插件走：卸掉插件，书文件夹和那份登记都还在原地；要彻底清空，得你自己动手——
删掉工作区里的书文件夹，再删掉 `~/.dsh/textbook/` 整个目录。

造出来的东西是教学参考。AI 会讲错——数据记错、结论下得太满、例子举得不合适，都可能。
交给学生之前，请老师或家长先过一遍。

## 换了电脑，或者把工作区挪了地方：书「不见了」

这是最容易吓到人的一种情况，先说结论：书没丢。

你会看到的是：打开原来那个会话，对话里的记录都还在；但工作台是空的，或者又回到了
「给新书起名」那一步；书文件夹明明就在硬盘上，双击也能打开。原因一句话：工作台靠
`~/.dsh/textbook/registry.json` 里记的一行找书，那行是绝对路径，建书那一刻写死，之后不跟着变。
你只要动过工作区——换了个盘、把项目复制到另一台电脑、或者把 dsh 的数据目录整个搬走——
它就认不出这些书了。

别自己去改文件。把下面这段原样发给你的造书会话（另开一个、选造书模式也行），它会替你改好：

> 我的书在工作台里认不出来了。书文件夹我找得到，现在在这个位置：〈把完整路径粘在这里〉
> 麻烦帮我把 `~/.dsh/textbook/registry.json` 里这本书的 `dir` 改成上面这个路径。
> ① 不要删掉那一行登记——它是这本书在工作台里唯一的入口，删了就再也找不回来；
> ② 改之前先把那个文件备份；③ 改完提醒我刷新一下界面。

把 `〈…〉` 换成书文件夹现在的完整路径（Windows 上点一下地址栏就能整条复制）。

真要搬，这两样要一起复制走，缺一不可：工作区里的书文件夹，和 `~/.dsh/textbook/` 整个目录
（里面是登记 `registry.json` 和你的 MinerU Token `settings.json`）。`settings.json` 里的 Token
是明文存的，备份时别放进网盘公开链接、也别随手发给别人。

## 卡住了，先看这里

下面这些是实际遇到过的问题；其余问题在各节里写着，按目录找。

| 你遇到的情况 | 怎么办 |
| --- | --- |
| 提示「需要先配置」 | 就是缺两把钥匙里的某一个：模型接口或 MinerU Token。配好后点「我配好了，继续」。 |
| 想中途加一章 | 先在对话里说。它会先判断能不能塞进现有章节；塞不进时不会自己加（这是有意的，防止书越写越散），会来问你。确实要加，就走「定点修改」重做下游，每一步仍会请你拍板。 |
| 担心花太多钱 | 花的是你自己那把模型接口的钱，本插件不收任何费用。想先看流程不花钱，就点「先建一本演示书试试」。注意：没有一道「超支就停」的硬闸，花多少由你那个接口的额度决定。 |
| 模式下拉里没有造书模式 | 多半是 dsh 太老，或者装到了旧版。先把 dsh 升到最新，再跑一次 `npx dsh-craft-your-textbook --upgrade`，然后新开一个会话。 |

## 想做一个自己的模式

在你自己 profile 的 `cordis.patch.yml` 里复制一份模式声明行、改出新身份（行上的 `id` 和
`config.id` 两个都要改），你就得到一个独立模式。别直接改插件包发出的那一行——profile 层的覆盖
每次启动都排在最后，升级也冲不掉。也别照旧教程 `mkdir` 建模式目录：dsh 早就不读它了。
