# 拆脚手架 + 交付质量门

> **定位（2026-08-27，ADR-0008）**：交付闸门已归一到机器 `runQualityChecks`（含本清单的乱码/章节数/必含板块/禁用词四项，判据从 style-spec/outline 读）。本文档降级为**终检时主 AI 操作的拆脚手架/自查清单参考**，不再作为第二套交付闸门（机器全绿即放行，不需要再人工 grep 一套）。拆脚手架的结果由机器 `scanScaffolding` 残留=0 强制兜底。

> **这是最关键、也最容易被跳过的一步**。实战教训：某本书的初版留了 112 个 `<!-- v2 新增 -->` 标记 + 8 个自检清单 + 8 个版本记录，审计后发现"AI 老师没法做对比"，两轮清理共删除 36,477 字符（-9.4%）。**这不是可选项，是交付前的硬门。**

> **⚠️ 本文所有 grep 命令的统一前提（Phase 6 终检与质量门都适用）**：Git Bash 下先 `export LC_ALL=C.UTF-8`，否则含中文/emoji 的匹配在 C locale 下按字节匹配会误判；或改用 `rg` / python 更稳。
>
> **脚本说明**：下文提到的 `strip_meta_sections.py` / `merge_book.py` 都指**你项目里那份副本**（从 skill 复制来、已按本书改过的，约定在 `<项目根>/scripts/`），不是 skill 目录里的原件。

## Phase 6 的三步分工

Phase 6 终检与交付包含三步，别混淆：

| 步骤 | 在什么上做 | 做什么 | 时机 |
| --- | --- | --- | --- |
| **终检** | **章源文件**（chapters/*.md、appendix/*.md） | 内容层扫查，趁还没合并、好定位好改 | 合并 BOOK.md **之前** |
| **拆脚手架** | 章/附录源文件 | 删除造书过程元数据，然后重跑合并 | 终检通过后 |
| **质量门** | **合并后的 BOOK.md** | 交付前最后 6 项硬门 | 交付前 |

> 终检和质量门有意重叠（禁用词、板块等两处都查）——终检是在源文件上早发现早改，质量门是在最终产物 BOOK.md 上的交付卡关。终检查得越干净，质量门越可能一次全绿。

## 为什么必须拆脚手架

**造书过程产生的所有元数据，对 AI 老师零价值。**

AI 老师只读最终这一本书。它没有旧版、没有"教师用书"、没有别的参照——所以书里任何"对比参照""修订日志""质检清单"都是噪音。

**口诀：拆完脚手架，书里只剩"教什么 + 怎么教"，没有"怎么造的"。**

## 必须拆除的 8 类过程元数据

| 类别 | 示例 | 为什么拆 |
| --- | --- | --- |
| ① 版本标记注释 | `<!-- v2 师生合版新增 -->` | AI 老师看不到旧版，标记无对照意义 |
| ② "新增内容"措辞 | "本单元新增了 X""追加 Y" | AI 老师没有"旧版"可对比 |
| ③ 自检清单 | `- [x] 🎬 场景具体（…）` | 这是造书者的 QA 打勾，不是教学内容 |
| ④ 版本记录 | `v1.0（初稿）：完成...` | 修订日志是作者维护笔记 |
| ⑤ 源教材引用 | "教师用书说…""教材原文指出…" | 转成"本单元…"直接陈述，不暴露来源 |
| ⑥ 造书者口吻 | "给人类教师读的""可追溯" | 转成给 AI 老师/读者的语气 |
| ⑦ 增量描述 | "v2.0 增量""在 v1 基础上追加" | 删掉版本相对性，只留绝对内容 |
| ⑧ 过程勾选项 | 自检清单里的 `- [x]` 打勾项 | 全删 |

## Phase 6 拆脚手架执行步骤

> **运行前提**：同终检/质量门——确保 UTF-8 locale（`export LC_ALL=C.UTF-8`），含中文/emoji 的匹配在 C locale 下可能误判。

**1. 跑脚本删除板块级元数据（对应上表 ③④⑧）**

```bash
python scripts/strip_meta_sections.py chapters/ appendix/
```

删除每个章/附录源文件中"META 声明的脚手架标题"到文件末尾的全部内容。脚手架标题列表从 META 读（每本书可能不同），不硬编码。

**2. 逐类搜索并清理行内元数据（对应上表 ①②⑤⑥⑦）**

搜索范围：**`chapters/` 和 `appendix/`**——附录同样会残留过程元数据，不可漏查。每类先跑 grep 确认命中位置，再用 Python 脚本批量替换（**不要用 Edit 工具逐条改——HTML 注释经常匹配失败**）。每次替换后重跑 grep 确认归零。

| 类别 | 搜索命令 | 处理方式 |
| ------ | --------- | --------- |
| ① 版本标记注释 | `grep -rn '<!--\|-->' chapters/ appendix/` | 整行删除含 `<!-- v` 或 `<!--v` 的 HTML 注释行 |
| ② "新增"措辞 | `grep -rn '新增\|追加\|新加\|v[0-9] 追加' chapters/ appendix/` | 删掉版本相对性措辞，只保留绝对内容 |
| ⑤ 源教材引用 | `grep -rn '教师用书说\|教材原文指出\|学生用书说\|原文指出' chapters/ appendix/` | 转成"本单元…"直接陈述，不暴露来源 |
| ⑥ 造书者口吻 | `grep -rn '给人类教师\|可追溯\|造书者\|人类教师' chapters/ appendix/` | 转成合适语气，或直接删除 |
| ⑦ 增量描述 | `grep -rn 'v[0-9]\.[0-9] 增量\|v[0-9] 基础\|在 v[0-9]\|基础上追加\|基础上补充' chapters/ appendix/` | 删掉版本相对性，只留绝对内容 |

全部归零后，再跑一轮综合兜底扫描确认无遗漏：

```bash
grep -rn 'v[0-9]\|<!--\|教师用书\|新增\|增量\|人类教师\|可追溯\|造书者' chapters/ appendix/ | grep -v 'AI 老师'
```

**3. 重跑合并**

```bash
# pure-blueprint 路线（保留章级 frontmatter）：
python scripts/merge_book.py

# human-readable 路线（剥离章级 frontmatter）：
python scripts/merge_book.py --strip-frontmatter
```

## Phase 6 质量门（6 项全绿才交付）
>
> **Iron Law 3 gate**：6 项硬门全绿 = 允许交付；任意一项不绿 = 返工（拆残留→重跑合并→重跑质量门），不以"接近全绿"放行。

> **运行前提**：见本文开头的 grep 统一前提（UTF-8 locale）。

| 检查项 | 方法 | 判据 |
| --- | --- | --- |
| ① 必含板块完整 | 按 style-spec §章内板块语法定义的必含板块 grep 计数 | = 章数 × 每章必含板块数（从 style-spec 读，不是硬编码 7 板块） |
| ② 禁用词 | 从 style-spec §正文语言风格 读本书特有禁用词表，grep BOOK.md；"AI"单独查后**人工确认** | = 0（"AI 老师"等合法词人工放行） |
| ③ 元数据残余 | grep META 声明的脚手架标题列表 | = 0 |
| ④ 章数 | 从 OUTLINE §逐章骨架 读预期章数，grep 章标题（格式从 style-spec 读，不是硬编码 `^# Unit`） | = 预期章数 |
| ⑤ 跨章引用 | 随机抽查 3 章，验证行内回溯/连接表/交叉引用指向的章/概念真实存在（Phase 5.3 已做全量检查，此步兜底抽查） | 无空指 |
| ⑥ 文件大小 | 合并后字节数 | **首本书**：记录本次字节数作为 baseline（见下）；**重跑时**：与上次 baseline 相比 ±10% |

**判据⑥ baseline 持久化方法**：baseline 写入项目根目录的 `.book-baseline` 文件（单行字节数），跨会话可读。

- 首本书记录：`wc -c < BOOK.md | tr -d ' ' > .book-baseline`
- 重跑对比：`CURRENT=$(wc -c < BOOK.md | tr -d ' '); BASELINE=$(cat .book-baseline); echo "current=$CURRENT baseline=$BASELINE";  DIFF=$(( (CURRENT - BASELINE) * 100 / BASELINE )); echo "diff=${DIFF}%"; [ "${DIFF#-}" -le 10 ] && echo OK || echo FAIL`

判据①②③④的具体值从四文件派生：

- 必含板块清单：读 style-spec §章内板块语法
- 禁用词表：读 style-spec §正文语言风格
- 脚手架标题：读 META #10 脚手架标题列表
- 章标题格式：读 style-spec §章标题格式
- 预期章数：读 OUTLINE §逐章骨架

**任何一项不过，修完重跑。**

> 注：判据②的禁用词表和判据③的元数据关键词需按具体项目调整（不同项目平台术语不同）。上方 grep 已用 `grep -v 'AI 老师'` 预过滤最常见的合法命中，剩余裸"AI"命中再人工确认——任何自动排除都可能漏检行尾/换行处的 AI。
