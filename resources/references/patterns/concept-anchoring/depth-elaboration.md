# 深度铺陈（Depth Elaboration）

> 四维定义与承诺档位以 `references/depth.md` 为单一事实源；本卡只讲怎么把已承诺的维度写出来。

## 解决什么教学问题
核心概念写出来只有"是什么"，缺深层理解——读者/AI 老师只能背定义，不懂原理、边界、脉络、专家权衡。无源（Mode A）造书时尤其明显。

## 什么时候用 / 什么时候不用
- 用：书里有需要学生真正"吃透"的核心概念（非背景性、非过渡性内容）；style-spec 深度承诺为"中/深"的维度
- 不用：纯叙事过渡、工具性说明（操作步骤、命令清单）；style-spec 声明"浅"的维度（承诺制，浅维不硬凑）
- 典型搭配：和 precise-definition 卡组合（定义后跟深度展开）；和 misconception 卡组合（边界/反例与误区互相印证）

## 长什么样（四维写法配方）

**机理**：追问"为什么"到三层——
1. 这个概念为什么是这样？（直接原因）
2. 这套机制/推导为什么有效？（深层原因）
3. 它成立的前提是什么？（前提假设）

**脉络**：问题史四连——
1. 这个概念为解决什么问题而生？（动机）
2. 谁/在什么背景下提出的？（来源）
3. 后来如何演变？（演化）
4. 至今有无争议 / 不同学派说法？（争议）

**边界**：找"反例集"——
1. 什么时候不成立？（失效条件）
2. 边界在哪？（适用域）
3. 和哪个易混概念怎么区分？（区分）

**专家视角**：问"内行会怎么想"——
1. 内行会权衡什么？（取舍）
2. 新手常踩什么坑？（坑）
3. 有没有量化精度 / 精确区分？（精度）

## 已知陷阱
- 为深而深：不服务于理解，变成掉书袋/堆史料（"深度不是灌水"）
- 只深机理不深其他：承诺了边界/专家视角却只展开机理
- 深但错：深度 gate 在正确性 gate 之后，杜撰的"深"比"浅而准确"更糟
- 全书深度不匀：范例章深，并行章浅（全书跨章结构审计中的深度一致性检查抓这个）

## 变体
- 认证书：深度集中在"专家视角/精度"——考点权重、命题陷阱、why-not 判断依据
- 入门概念书：深度集中在"机理/脉络"——为什么是这样、从哪来
- blueprint 路线：深度展开可放在元指令块（💬引导方向里写"引导学生推导机理"）

## 不要这样用
- 不要对 style-spec 声明"浅"的维度硬铺陈
- 不要把深度展开塞进 Definition 卡（Definition 只做原文+大白话双讲，深度放正文或专门板块）
- 不要用"更长的定义"冒充深度——深度是新的信息维度，不是字数
