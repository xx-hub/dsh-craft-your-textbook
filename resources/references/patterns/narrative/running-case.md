# 贯穿案例语料库（Running Case）

## 解决什么教学问题
怎么用一个贯穿全书的虚构项目/公司/场景，为所有章提供连续的情境素材，制造"上一章我们在这个项目上是怎么判断的"的连续感，避免各章情境碎片化。

## 什么时候用 / 什么时候不用
- 用：需要跨章连续情境的书（认证/技能/入门都适用）
- 不用：纯参考手册；每章主题完全独立的文集；纯工具书
- 典型搭配：几乎必配 scenario-hook（章首钩子挂靠贯穿案例）；可选搭配 character-protagonist（案例里加主角）
- 与 character-protagonist 的关系：两者可独立选择——PMP 用 running-case 但不要主角；CPA 两者都用；入门教材可以只用 running-case 不写人物

## 长什么样（结构示例）

PMP OUTLINE（只用 running-case，不写主角）：
```markdown
**贯穿案例弹药**（非小说主角，只作 AI 老师提问的情境语料）：全书统一挂靠一个虚构的**建筑企业数字化转型项目**——

> **锦程建工集团承接的"市中心医院综合体"项目**（金额约 8 亿，工期 30 个月）。项目天然含两条线：
> - **预测型主体**（Ch1-12 主要取材）：土建 / 机电 / 装修三大标段，固定总价合同，分包商 5 家，业主 + 监理 + 政府质监三方治理，用关键路径法排程、挣值管理控成本。
> - **敏捷型配套**（Ch13-15 主要取材）：为项目自研的 **BIM 协同平台 + 进度管理 App**，由内部软件团队用 Scrum 双周迭代开发。

各章情境钩子都挂靠此项目，制造"上一章我们在这个项目上是怎么判断的"的连续感。**但不写人物情感弧线、不切支线主角、不用第二人称小说**——项目只作情境语料库，人物仅作场景中的角色（项目经理、监理、分包负责人等），不展开个人故事线。
```

CPA（running-case + 主角老周，两者都用）：
- 贯穿公司：华明制造（A 股上市精密零部件制造企业，资产 12 亿，营收 8 亿）
- 贯穿主角：老周（投资者/报表使用者视角）+ 注册会计师（专业人士视角）
- 各章情境从华明制造的不同业务场景切入（收入确认/存货盘点/关联交易……）

结构要点：
- 在 OUTLINE.md 里声明贯穿案例是什么（不放在 META 或 style-spec）
- 给出具体数字/角色/约束，让各章写作 agent 可以直接引用
- 声明**边界**：明确说清"案例做什么"和"案例不做什么"——
  - PMP 边界："不写人物情感弧线、不切支线主角、不用第二人称小说"
  - CPA 边界：可以写老周的心理活动和判断过程，但不展开个人生活线
- 案例设计要考虑"能不能覆盖全书各章的教学需要"——PMP 的医院项目天然含预测型+敏捷型两条线，覆盖全书 18 章

### 抗迁移失败补丁（PMP 实战经验）
贯穿案例的行业是固定的（PMP 用建筑，CPA 用制造业），但考试/实战中学生会遇到完全不相关的行业情境。因此**章末速判/练习题必须刻意跳出贯穿案例的行业**——PMP 速判脚本用制药/IT/跨国/快消等不同行业；CPA 练习题用商贸/服务业等不同行业。主线案例只用于章首情境钩子和探索脚本，训练"判断依据可跨行业迁移"的能力。因此章末速判/练习题必须刻意跳出贯穿案例的行业——不同行业情境训练"判断依据可跨行业迁移"的能力。主线案例只用于章首情境钩子和探索脚本。

## 已知陷阱
- 贯穿案例太复杂（多条故事线交织、多角色视角切换）——写作 agent 把握不住，把案例写成小说。案例是"弹药库"不是"剧情线"，保持简单：一个公司/一个项目/一个场景足矣。
- 只在 OUTLINE 声明但各章钩子不挂靠——案例白设计，丢了连续感。应逐章检查钩子是否挂靠了贯穿案例。
- 所有练习都用贯穿案例的行业（见上方"抗迁移失败补丁"）——考场遇陌生行业不会判断，迁移失败。
- 贯穿案例被写成小说主线——违背"要案例弹药不要小说"原则。认证类蓝本尤其注意：案例是情境素材库，不是主线剧情。

## 变体
- **项目型**：一个虚构项目贯穿全书（PMP 医院项目/编程的电商平台开发/工程的桥梁建设）
- **公司型**：一个虚构公司贯穿全书（CPA 华明制造/经济学的虚拟岛国/商科的连锁餐饮企业）
- **人物型**：一个虚构人物的成长/旅程（搭配 character-protagonist 卡，如"从实习生到项目经理"的两年）
- **多案例切换**（不推荐）：每章用不同案例——失去了"连续感"这个 running-case 的核心价值，不如直接用 scenario-hook 独立钩子

## 不要这样用
- 把 running-case 写成需要多卷长篇小说式展开的剧情——案例是情境素材库不是主线剧情，每次引用 2-4 段钩子就够
- 认证类蓝本（PMP 风格）给 running-case 加主角情感弧线——认证类的核心是判断依据可迁移，不是人物代入感
- 在 running-case 里塞进全书所有知识点（"这个项目要覆盖所有 ECO 任务"）——案例是"情境载体"不是"知识清单"，有些知识点天然不适合塞进同一个案例
