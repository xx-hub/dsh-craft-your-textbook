# 写作小助手 prompt 模板（并行铺章）

> ⚠️ **并发上限（硬约束，票 `walkthrough-fixes/19`②）**：主笔**一次最多派
> `maxConcurrentSubagents` 个小助手**（默认 3；dsh 侧按交办件与账上那个数，skill 侧由主笔自己定）。
> 到上限就等一个回来再派下一路——这是硬约束不是建议，⛔ 不许「嘴上答应、实际多派」。
>
> **槽位由派发方填：dsh 由机器填、skill 侧由主笔填。** 下面所有花括号槽位都由派发方填。
> 派单正文由派发方按本模板填：dsh 侧机器代填，skill 侧主笔照模板手填。模板即契约——缺项 = 该 agent 开工前看不到关键约束。
> 本模板是 `audit-and-testing.md §九` 的单一事实源；改契约改这里，别改两处。
> 占位符里的路径都以本项目实际产物为准（下面每条都给了"通常是"的写法）。

## 登记表口径（派发时随活一起给你，不靠主笔措辞）

主笔派活时会随 prompt 给你**两行清单**，它们来自这本书的产物登记表，不是主笔临时写的措辞：

- **你该读的登记行** —— 每行一句「这份管什么／什么时候要」＋ 一个精确路径。你只读这几行指向的东西。
- **你该产出的登记行** —— 每行一个落盘点（角色 ＋ 路径）。**你的产出必须落在这些路径上**，别的路径不算交工。

边界以那两行为准：**清单没列的产物不许产出，清单列了的不许漏**。登记表里 `pointer` 那一档是
「只给你一行 ＋ 路径，要读时自己回读那一节」；`inline` 那一档（今天只有工具纪律 §九 那一页纸）正文已经在你上下文里；
`never` 那一档一个字都不会给你。

⚠️ 三件套照旧、不因这一节改变：**细目落盘 ＋ 最终回复 ≤N ＋ 回灌结构（结论／条目级点名／落盘路径）**
（单一事实源是 `audit-and-testing.md §九` 的「回灌三件套」）。

## 必带内容（按顺序）

1. **金标准章全文**（作为范例）——`{{金标准章路径}}`（即范例章）。让 agent 先读它，作为"这书长什么样"的锚。
2. **四份约束文件全文**——给全文，别只给摘要：
   - `{{style-spec.md 路径}}`（写作规范：模式选型结论、章内板块语法、叙事约定、正文语言风格、深度四维承诺表、防幻觉铁律、写作纪律、脚手架标题清单）——通常是 `style-spec.md`
   - `{{outline.md 路径}}`（章节骨架：每章的 title/outline/source/targetWords/points/体量依据 + 范例章号）——通常是 `OUTLINE.md`
   - `{{explore.md 路径}}`（源材料索引／源探查报告：材料清单+角色标签、结构观察、教学线索）——通常是 `源材料索引.md`
   - `{{知识点清单路径}}`（主笔合并的知识点清单：知识点／可判／出处／把握／标记）
3. **本章源材料映射**：outline 里本章的 `source` 字段指向哪本材料的哪一节，定位到 `{{材料/转换稿 材料路径}}` 的对应小节，精确到小节标题/行号——`{{材料/转换稿 材料路径}}` 的 `{{本章源材料小节}}`。
4. **防幻觉铁律完整 4 条**（`audit-and-testing.md §6.4`）：打赌测试 / 追不到源就降级 / 最危险条目逐字回源 / 偏好断言必标判断根。
5. **不变量底线**：从 `references/invariants.md` 读适用本路线的编号——`{{pure-blueprint: I1-I9}}` / `{{human-readable: I1-I4 + I7-I9 + H1-H3}}`。
6. **本章在知识链中的位置 + 跨章引用指向**：前面哪章讲过什么、后面哪章会用到这里——见下面「知识链（按图现算）」那一节（按这本书的图逐条填好；dsh 侧由机器现算，skill 侧由主笔按《知识点清单》的拓扑两节现算）。
7. **本章深度承诺 + 四维自问**：从 `{{style-spec.md 路径}}` §深度四维承诺表摘出本章相关承诺给 agent。写作完成时，对本章核心概念逐个过 `references/depth.md` 判定问题自问（读者能回答"为什么"吗 / 知道它从哪来、有何争议吗 / 知道边界吗 / 像内行写的吗），自问结果写进完工回报。
8. **本章知识点清单 + 前向引用粒度规则**：
   - 从 `{{outline.md 路径}}` 里本章的 `points` 字段读出本章必须覆盖的知识点清单（一个知识点一条），写完逐条打钩，不能有知识点遗漏。
   - **前向引用粒度规则**：正文里提到还没写的章节时，只引用大纲已承诺的范围（如"第 X 章会展开 Y"），**禁止编造未写章节的具体数字、结论、例题**；拿不准就写"后面章节会展开"或干脆不写，绝不用编的细节填空。

## 章末教学区里的带读手册（按 route 写，⛔ 不加新的一节）

章末 **H2 教学区**早就存在：它是本书板块表里声明的那一节，位置与形态照 `{{style-spec.md 路径}}` 的「章内板块语法」与「章末教学区规范」写。**带读手册是教学区内部的第一块内容，不是章里新开的一节**：⛔ 不加二级节、⛔ 不动板块表顺序、⛔ 不把手册搬到章首或书末。⛔ **不照抄金标准章的手册内容**——范例章全文会作为「这书长什么样」的锚进每一个执笔的 prompt，照抄会让十章变成一份。

- **human（自己也要读）**：**零改动。** 教学区原样保留三层问题链（回忆／迁移／开放）与内嵌提示，你一个字都不用多写；⛔ 不新增段落、⛔ 不改字数、⛔ 不动板块名。
- **blueprint（只让 AI 老师读）**：教学区第一块写带读手册，四个子项按顺序（子项名逐字照 `style-spec` 声明的用；没声明就用默认名）：
  1. **本章骨架与课堂顺序**：本章讲什么、先讲哪块后讲哪块、每块大致花多少时间。
  2. **三档题与提示分级**：检查／应用／再想一层三档；每题带分级提示——第一提示指方向、第二提示给关键步、最后才给答案。
  3. **误区五字段**：错因名／长什么样／为什么会错／老师怎么问／怎么自查。
  4. **图与实物的文字版**：坐标、构图清单等文字化描述，连同课堂节奏与「卡住了怎么办」。

**题目与误区优先从 `{{知识点清单路径}}` 派生，不要现编**：检查档对清单里 `testable` 那一句、应用档对拓扑里 `prereq` 的跨越、再想一层对本章最后一节的边界；误区对先修边与本章的高频错法。只写「老师可以怎么问」的**方向与顺序**，⛔ 不写「老师说…学生答…」的闭合台词（守 I5）。

**正文不许拿块头形状冒充板块名**：手册的块名（英文 `Definition:`／`Common Misconception`／`Concept Check`／`Exercises`／`Think Deeper`，以及中文「短行＋冒号」块头）只属于手册内部。正文（教学区之前）按本书板块表逐字写；板块表外不出现「短行＋冒号」的块头——标题行／加粗行／纯标签行都算，**表格行只在单元格等于板块名或以它起头时才算**，引用行不算（表格本身是内容，允许用）。

## 知识链（机器现算）

**这一节告诉你「写这一章时手上要先有谁、后面谁要用到它」**：本章每个 `points` 的 `prereq` 上游传递闭包
（按距离分层：第 1 层直接前置**详给**名字 ＋ 一句 `testable` ＋ 归第几章 ＋ 位置索引，第 2 层及更远
只给名字）＋ **直接后继**，按这本书的拓扑现算（dsh 侧由机器读图，skill 侧由主笔读《知识点清单》的拓扑两节）。

- ⛔ **不抄原文**：这一节只给名字与位置索引——要读原文，照索引回材料那一份（`资料N 第a–b 行`）。
- ⛔ **是提示不是约束**：`outline` 的 `points` 与章节顺序一个字都不许因为这一节改；哪条前置「真讲过」由你与跨章审计判。
- 同一层里**与本章同章的**前置按本章 `points` 数组下标排在前面；图上被人划掉的卡**留着并带一句标记**（那是人的裁决，⛔ 不剪、不传播）。

## 风格线（必带、必逐条落实）

- **给全文**：`{{style-line.md 路径}}`（风格线镜像——用户对写法的要求汇总，通常是 `style-line.md`）。它与上面四份约束文件**同等地位**，不是"参考一下"。
- **动笔前逐条读**，写完对着每一条自查有没有落实；有没落实的在完工回报里写明是哪一条、为什么。
- **与写作规范打架时以风格线为准**（那是用户的原话），并在完工回报里点出冲突点让主 agent 裁决。
- **文件不存在 ≠ 这条不用管**：只说明用户还没提过风格意见；交章前让主 agent 再确认一次有没有新增的风格线（用户随时可能补）。

## 纪律要点（必告知 agent）

- **工具纪律（跨平台）**：文件 I/O 用文件工具（read / write / edit / glob / grep），shell 只留给真需要 shell 的场景且用前说明理由；规则对 Windows / macOS / Linux 完全一致，不点名单一 shell 名。单一事实源 `audit-and-testing.md §九 工具纪律`（别处不另写一份）。
- **正文不写出处**：`知识点清单` 的「出处」列、本章源材料映射的行号，是给你**回源核对**用的工具，⛔ 不写进正文——不写 `（出处：S1 第一章；附录 B 可查）`、不写 `S3 第 18 章`、不写 `（S7 296）`、不写 `资料2 第 300–320 行`。需要说明"这是谁的说法"时用自然语言（"有一种做法认为…"）；点名书名只在本书写作规范明确允许的板块里出现（如「说法不一」那一节）。出处收进章末表或附录是主笔在交付那一跳的事，不归你。
- **写作 agent 的自审不算审计**：完工后独立审计由主 agent 另派（普通章用 `subagent-prompts/audit-agent-prompt.md`；金标准章用 `subagent-prompts/gold-audit-prompt.md`）。你的自报清单不能替代独立审计。
- **模型**：写作 = 标准档。聚焦本章，不做全书级判断。
- **完工回报契约**：返回时写清楚——写了哪些文件、每章板块是否齐全、知识点清单是否全部打钩、对写作规范的遵守情况、有没有跳过/改动的板块、有没有需要主 agent 注意的存疑点。**不要在回报里写"已审计通过"。**
- **回灌三件套**（形状与逐类一档表的单一事实源是 `audit-and-testing.md §九`「回灌三件套 · 单一事实源」，别处不另写一份；写作这一档 **≤1K token**）：**① 细目落盘**＝章稿本体写进**你这一路的分片** `{{本章分片路径}}`（NN＝章号、MM＝这一路的号，都两位；主笔派活时告诉你 MM 是几），回报里**只留指针、不抄正文**；**② 最终回复 ≤1K token**；**③ 回灌结构＝结论（写完／没写完）＋ 条目级点名（缺哪个知识点、哪块板块没齐，要点到具体那一条）＋ 落盘路径（那份分片的准确路径）**。超预算时只留指针，细目去那份分片里看——文件本来就在，谁要看谁自己读。

## 章正文不归你写：你只落分片（机器拼）

- ⚠️ **`{{章正文路径}}` 由主笔跑拼章脚本拼，你一个字都不许往里写**（写了交办方也会拒收：那边只认「盘上那份正文＝各片分片的拼装件」；dsh 侧这一步由机器做）。
- 你写的是 `{{本章分片路径}}`——**一路一个号**（主笔派给你的是 `-01`、`-02`… 中的哪一个，就以它为准）。
- 一章只派一路时就是 `-01` 一片；主笔把一章拆成两路（各写一半）时是 `-01` ＋ `-02`，按号升序把两片接起来。
  ⇒ **同一个文件不会被两个写者同时写**；但这**不是**「各写各的、最后谁赢」——两片都会被拼进正文，**别把整章的活重做一遍**，只写主笔交给你那一段。
- 分片落齐后**由主笔跑 `python scripts/assemble_chapter.py .` 拼**（不是你去拼，也不要求你去检查拼出来的那一份）。
- **深度自问不算审计**：深度四维自问写进完工回报，但独立审计由主 agent 另派——自问只是让写作者留意，不能替代审计。
