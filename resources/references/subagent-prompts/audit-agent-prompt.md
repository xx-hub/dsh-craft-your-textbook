# 审计 subagent prompt 模板（独立审计）

> 主 agent 派审计 subagent 时用它。核心铁律：**干净上下文、从零读、只报告不改文件**（`audit-and-testing.md §6.1 + §7.0`）。
> 审金标准章（范例章）用 `subagent-prompts/gold-audit-prompt.md`——它额外要求必读文档矩阵并产出带 matrix 的 `work/audit-<NN>.md`。

## 必带内容

- **审计对象**：`{{审计对象：范例章 / 某章 / 附录 / 约束文件路径}}`（通常是 `work/chapter-<NN>.md`、`work/outline.md`、`work/style-spec.md` 等）
- **约束文件**（审章时）：`{{style-spec.md 路径}}`、`{{outline.md 路径}}`、`{{explore.md 路径}}`、`{{knowledge-map.json 路径}}`
- **权威源**（有源场景）：`sources-md/{{材料文件}}.md`（`{{源文件路径}}`）

## 审计要求

1. **上下文干净**：从零读产出文件 + 约束 + 权威源。不看建造日志、不看造书过程对话。你不知道"这本书是怎么造的"。
2. **只报告、不改文件**：每条结论给证据（文件 + 行号 + 原文）。不要直接改文件。
3. **逐条对照**：
   - 对照 `style-spec.md`（写作规范）：本书定位、防幻觉铁律、读者意识声明、章内板块语法、章末教学区规范、写作纪律、frontmatter schema（如有）、AI 老师使用方式、防螺旋铁律、脚手架标题列表——逐条打钩，重点核**章内板块语法**与**写作纪律**
   - 对照 `outline.md`（章节骨架）：标题匹配、本章 `outline` 声明的核心问题是否全部回答、`points` 知识点清单是否全部覆盖、覆盖目标（考纲任务/课标/知识域）完整兑现、判断根锚定回扣
   - 对照 `explore.md` + `knowledge-map.json`（源材料索引/知识地图）：预抽关键条目全部覆盖、硬记锚无遗漏、高频陷阱被提及
   - **"说清楚了吗"测试**：完全没学过该领域的读者，读完能否自己说清本章标题承诺的核心概念
   - **贯穿案例一致性**：案例具体可触摸？概念从案例自然引出？
   - **自测题质量**：原创？跨行业 ≥3？解析说清"为什么对、为什么错"？
   - 对照 `style-spec.md` §深度四维承诺表：用 `references/depth.md` 判定问题逐维核对，判"兑现/未兑现" + 证据（文件+行号+原文）
4. **严重度分级**：P0 必改 / P1 应改 / P2 可改。每条结论标 ✅/⚠️/❌。
   - 深度未兑现：至少 P1（应改）；核心概念整维缺失（承诺"中/深"却完全没展开）→ P0（必改）
5. **完整报告在最终消息返回、不中途停**：不要读几个文件就返回一句"我去核对"。

## 风格线（必带、必逐条核对）

- **给全文**：`{{style-line.md 路径}}`（风格线镜像——用户对写法的要求汇总，通常是 `work/style-line.md`；项目里没有这份文件就记一句"用户还没提过风格意见"，别把这一节跳过）。
- **逐条对照**：正文有没有落实用户的每一条风格要求？没落实的按严重度分级报出来——用户点名的风格点落空至少 P1（应改），整条被无视且影响全书风格基调的判 P0（必改）。每条给证据（文件 + 行号 + 原文）。
- **与 `style-spec.md` 打架时以风格线为准**（那是用户的原话），并在报告里点明冲突在哪，别自行替用户改判据。

## 纪律要点（必告知 agent）

- **工具纪律（跨平台）**：文件 I/O 用文件工具（read / write / edit / glob / grep），shell 只留给真需要 shell 的场景且用前说明理由；规则对 Windows / macOS / Linux 完全一致，不点名单一 shell 名。单一事实源 `audit-and-testing.md §九 工具纪律`（别处不另写一份）。

## 主 agent 收到报告后（§6.2 / §八）

- **逐条回权威源核实**再改，不照单全收。审计员也会误判或误读。
- 修法的最终依据是权威源/方案设计，不是审计报告本身。
- 发现缺口时问"根因在约束文件吗？"——在 → 按 §八 回填约束文件（修章 + 修 style-spec/outline/explore）。
- 章级审计的最终结论由主 agent 落成 `work/audit-<NN>.md`（机器按章验收要求每章都有该文件；金标准章的含 matrix 版本见 `gold-audit-prompt.md`）。
