# 审计 subagent prompt 模板（独立审计）

> ⚠️ **并发上限（硬约束，票 `walkthrough-fixes/19`②）**：主笔**一次最多派
> `brief.maxConcurrentSubagents` 个小助手**（默认 3；用户在拍板前拧过就按交办件与账上那个数）。
> 到上限就等一个回来再派下一路——这是硬约束不是建议，⛔ 不许「嘴上答应、实际多派」。

> 主 agent 派审计小助手时用它（本仓工作台内 `workbench_act(action=agent-assign, dispatchKind=audit)`，派单正文由机器按模板代填）。核心铁律：**干净上下文、从零读、只报告不改文件**（`audit-and-testing.md §6.1 + §7.0`）。
> 审金标准章（范例章）用 `subagent-prompts/gold-audit-prompt.md`——它额外要求必读文档矩阵并产出带 matrix 的 `工作区/audit-<NN>.md`（本仓工作台内派发档：`workbench_act(action=agent-assign, dispatchKind=gold-audit)`）。
>
> ⭐ **你可以把认领的活再拆给下级审计员**（`audit-and-testing.md §6.1`「先派、后读、再合」）：
> 认领的章节多、下级审计员多于一个时，**本仓造书工作台内**走 `workbench_act(action=agent-assign, dispatchKind=audit)`（章级；范例章那一档是 `dispatchKind=gold-audit`）把它们**分别派给几个下级审计员**——派单正文由机器按模板代填；**Claude 独立运行时**才用平台的 subagent 调度工具。
> **你自己不读正文，只汇总他们的报告**——每份报告按下面的要求给证据（文件 + 行号 + 原文），
> 你做的是合并与去重，不是复核正文。**派发的那一刻你手里不许已经有任何一章正文**：
> 先读了再派下去，这一路审计的"我核过了"就全部不可信（那正是 §6.1 那条病）。
> ⚠️ 派工**不许改用打断重来那套**（`interrupt_agent` 是「暂停后收回小助手」专用的）；也不许让下级审计员读你自己的上下文。

## 登记表口径（派发时随活一起给你，不靠主笔措辞）

主笔派活时会随 prompt 给你**两行清单**，它们来自这本书的产物登记表，不是主笔临时写的措辞：

- **你该读的登记行** —— 每行一句「这份管什么／什么时候要」＋ 一个精确路径。你只读这几行指向的东西。
- **你该产出的登记行** —— 每行一个落盘点（角色 ＋ 路径）。**你的产出必须落在这些路径上**，别的路径不算交工。

边界以那两行为准：**清单没列的产物不许产出，清单列了的不许漏**。登记表里 `pointer` 那一档是
「只给你一行 ＋ 路径，要读时自己回读那一节」；`inline` 那一档（今天只有工具纪律 §九 那一页纸）正文已经在你上下文里；
`never` 那一档一个字都不会给你。

⚠️ 三件套照旧、不因这一节改变：**细目落盘 ＋ 最终回复 ≤N ＋ 回灌结构（结论／条目级点名／落盘路径）**
（单一事实源是 `audit-and-testing.md §九` 的「回灌三件套」）。

## 必带内容

- **审计对象**：`{{审计对象：范例章 / 某章 / 附录 / 约束或基础设施文件路径}}`（通常是 `工作区/chapter-<NN>.md`、`工作区/outline.md`、`工作区/style-spec.md` 等）。⚠️ 审章时被审正文是 **`工作区/chapter-<NN>.md` 那一份**——它**由机器从分片拼**（主笔在派你之前已经叫机器拼过一次）；`工作区/分片/chapter-<NN>-<MM>.md` 是执笔小助手的原材料，**不是你的审计对象**（读它容易把「两片之间接不上」这类问题漏掉：机器拼出来的那一份才是读者会看到的东西）。
- **约束文件**（审章时）：`{{style-spec.md 路径}}`、`{{outline.md 路径}}`、`{{explore.md 路径}}`、`{{knowledge-map.json 路径}}`
- **权威源**（有源场景）：`材料/转换稿/{{材料文件}}.md`（`{{源文件路径}}`）

## 审计要求

1. **上下文干净**：从零读产出文件 + 约束 + 权威源。不看建造日志、不看造书过程对话。你不知道"这本书是怎么造的"。
2. **只报告、不改文件**：每条结论给证据（文件 + 行号 + 原文）。不要直接改文件。
3. **逐条对照**：
   - 对照 `style-spec.md`（写作规范）：本书定位、防幻觉铁律、读者意识声明、章内板块语法、章末教学区规范、写作纪律、frontmatter schema（如有）、AI 老师使用方式、防螺旋铁律、脚手架标题列表、**多源同级声明**（无条件节：**无论本书有几份材料，都必须写这一节**——两份并行的权威源说法不同时，写作规范里要逐字点出「以哪本为准 + 理由」；只有一份源或几份说法一致时，写「本书无并行权威源，不存在同级冲突」；这一节整个没有就当**没答**报出来，不许替它挑一本）——逐条打钩，重点核**章内板块语法**与**写作纪律**
   - 对照 `outline.md`（章节骨架）：标题匹配、本章 `outline` 声明的核心问题是否全部回答、`points` 知识点清单是否全部覆盖、覆盖目标（考纲任务/课标/知识域）完整兑现、判断根锚定回扣
   - 对照 `explore.md` + `knowledge-map.json`（源材料索引/知识地图）：预抽关键条目全部覆盖、硬记锚无遗漏、高频陷阱被提及
   - **"说清楚了吗"测试**：完全没学过该领域的读者，读完能否自己说清本章标题承诺的核心概念
   - **贯穿案例一致性**：案例具体可触摸？概念从案例自然引出？
   - **自测题质量**：原创？跨行业 ≥3？解析说清"为什么对、为什么错"？
   - 对照 `style-spec.md` §深度四维承诺表：用 `references/depth.md` 判定问题逐维核对，判"兑现/未兑现" + 证据（文件+行号+原文）
4. **严重度分级**：P0 必改 / P1 应改 / P2 可改。每条结论标 ✅/⚠️/❌。
   - 深度未兑现：至少 P1（应改）；核心概念整维缺失（承诺"中/深"却完全没展开）→ P0（必改）
5. **完整报告落盘 `工作区/audit-<NN>.md`、最终回复只回摘要、不中途停**（NN＝本章号）：
   - **形状照 `gold-audit-prompt.md`**：产出不是聊天报告，而是**落盘 `工作区/audit-<NN>.md` 的严格 JSON**——`{"passed": true|false, "issues": [{"level": "错误|警告|提示", "status": "open|fixed|accepted-risk", "text": "哪份文件哪一行、什么问题、为什么、建议怎么改"}]}`（`accepted-risk` 还要写 `reason` 与 `confirmedBy`；改完把该条 `status` 回写 `fixed`），机器按章验货读的就是它——**`passed` 由机器按 issues 现算，自报 true 不能洗绿**。**产出不是被审文件**：你落的是**你自己那份产物**，被审的正文与约束文件一个字不许动（顶部「只报告不改文件」铁律原样，落下自己的产物不违反它）。
   - **不中途停**：不要读几个文件就返回一句"我去核对"——**这条治的是早退，不是长度**；它与下面的 ≤2K 是两条不同的力，压预算不许压到这条上。
   - **回灌三件套**（形状与逐类一档表的单一事实源是 `audit-and-testing.md §九`「回灌三件套 · 单一事实源」，别处不另写一份；章级审计这一档 **≤2K token**）：**① 细目落盘**＝逐条证据（文件＋行号＋原文）写进 `工作区/audit-<NN>.md`；**② 最终回复 ≤2K token**；**③ 回灌结构＝结论（通过／不通过）＋ 条目级点名（每条点到文件＋行号）＋ 落盘路径 `工作区/audit-<NN>.md`**。压预算压的是"把完整逐条证据也抄进回复"，不是压证据本身。

## 风格线（必带、必逐条核对）

- **给全文**：`{{style-line.md 路径}}`（风格线镜像——用户对写法的要求汇总，通常是 `工作区/style-line.md`；项目里没有这份文件就记一句"用户还没提过风格意见"，别把这一节跳过）。
- **逐条对照**：正文有没有落实用户的每一条风格要求？没落实的按严重度分级报出来——用户点名的风格点落空至少 P1（应改），整条被无视且影响全书风格基调的判 P0（必改）。每条给证据（文件 + 行号 + 原文）。
- **与 `style-spec.md` 打架时以风格线为准**（那是用户的原话），并在报告里点明冲突在哪，别自行替用户改判据。

## 纪律要点（必告知 agent）

- **工具纪律（跨平台）**：文件 I/O 用文件工具（read / write / edit / glob / grep），shell 只留给真需要 shell 的场景且用前说明理由；规则对 Windows / macOS / Linux 完全一致，不点名单一 shell 名。单一事实源 `audit-and-testing.md §九 工具纪律`（别处不另写一份）。

## 主 agent 收到报告后（§6.2 / §八）

- **逐条回权威源核实**再改，不照单全收。审计员也会误判或误读。
- 修法的最终依据是权威源/方案设计，不是审计报告本身。
- 发现缺口时问"根因在约束文件吗？"——在 → 按 §八 回填约束文件（修章 + 修 style-spec/outline/explore）。
- **章级审计的结论由审计员自己落成 `工作区/audit-<NN>.md`**（机器按章验收要求每章都有该文件；金标准章的含 matrix 版本见 `gold-audit-prompt.md`）。**不是主 agent 从你的回报里转写**——那正是「小助手全文回流 ＋ 主笔再抄一遍落盘」的双重搬运（票 context-budget/06 实测：回流 4,645–11,532 字符 ＋ 主笔 write 入参 3,558／2,567 字符）。主 agent 收到报告后做的事是**逐条核实与裁决**（§6.2），不是搬运。
