# 跨章审计小助手 prompt 模板（合并前全书一致性核对）

> ⚠️ **并发上限（硬约束，票 `walkthrough-fixes/19`②）**：主笔**一次最多派
> `brief.maxConcurrentSubagents` 个小助手**（默认 3；用户在拍板前拧过就按交办件与账上那个数）。
> 到上限就等一个回来再派下一路——这是硬约束不是建议，⛔ 不许「嘴上答应、实际多派」。

> 主 agent 在全章过目之后、机器合并成书**之前**派它。核心铁律与另外两份审计模板同款：
> **干净上下文、从零读、只报告不改文件**（`audit-and-testing.md §6.1 + §7.0`）。
>
> **它与章级审计的区别**：章级审计（`audit-agent-prompt.md`）审的是「这一章写对没有」，
> 金标准章审计（`gold-audit-prompt.md`）审的是「范例章兑现了设计没有」；**这一份审的是
> 「这本书拼起来对不对」**——它的对象是**整本书的一致性**，输入是**全部章**而不是一章。
> 所以它不产 `工作区/audit-<NN>.md`（那是章族的落盘契约），它产 **`工作区/audit-cross.md`**。
>
> ⚠️ **派发那一刻主 agent 手里不许有任何一章正文**（`audit-and-testing.md §6.1`「先派、后读、再合」，
> 硬约束，不做例外）。它读完书再派，这一路审计的「我核过了」全部不可信——2026-10-02 实测正是
> 这么静默不做的：merge 段主笔窗口 **+0 token**，一个章都没读，凭协调记忆写出了那份审计记录。
>
> ⚠️ **五项判定词与判定口径只住在下面「五项核对判定表」这一节**——交办说明、方法论文档、
> 拒收文案、造书模式人设一律只**引**这份模板，不各写一份清单（那是会漂的五份平行清单）。
>
> **回灌三件套**（细目落盘 ＋ 最终回复 ≤N ＋ 回灌结构）的形状与逐类一档表的单一事实源是
> `audit-and-testing.md §九`「回灌三件套 · 单一事实源」，本模板下面「严重度与回灌三件套」那一节照它写。

> ⚠️ **第五项「边界越界」已落**（票 `reader-cognition-boundary/09` 裁、`reader-cognition-boundary-build/08` 落，
> 决定落 `docs/adr/0042`）：它并进**这一道**、排在逐边清单（第 4 项）之后，判的是「讲了读者已经会的／
> 讲了授权砍掉的／讲了超出这本书能教到的知识范围的内容」三档。结论**只点名、由人裁**（⛔ 不派修复小助手自动改、
> ⛔ 不进用户意见队）。判定词与判定口径只在下面判定表里，**改词改表一处**。

## 登记表口径（派发时随活一起给你，不靠主笔措辞）

主笔派活时会随 prompt 给你**两行清单**，它们来自这本书的产物登记表，不是主笔临时写的措辞：

- **你该读的登记行** —— 每行一句「这份管什么／什么时候要」＋ 一个精确路径。你只读这几行指向的东西。
- **你该产出的登记行** —— 每行一个落盘点（角色 ＋ 路径）。**你的产出必须落在这些路径上**，别的路径不算交工。

边界以那两行为准：**清单没列的产物不许产出，清单列了的不许漏**。登记表里 `pointer` 那一档是
「只给你一行 ＋ 路径，要读时自己回读那一节」；`inline` 那一档（今天只有工具纪律 §九 那一页纸）正文已经在你上下文里；
`never` 那一档一个字都不会给你。

⚠️ 三件套照旧、不因这一节改变：**细目落盘 ＋ 最终回复 ≤N ＋ 回灌结构（结论／条目级点名／落盘路径）**
（单一事实源是 `audit-and-testing.md §九` 的「回灌三件套」）。

## 审计对象（派发时逐条填实际路径）

- **全部章正文**：`{{全部章路径清单}}`（通常是 `工作区/chapter-01.md` … `工作区/chapter-<NN>.md`，一位都不能少）。
- **章节骨架**：`工作区/outline.md`（每章承诺的 title / outline / points —— 拿它当「本书承诺了什么」的唯一真相源）。
- **结构化知识地图**：`工作区/knowledge-map.json`（knowledgePoints / chapterSuggestion —— 知识点与归属章）。
- **写作规范**：`工作区/style-spec.md`（术语口径、命名约定、跨章引用粒度规则）。
- **风格线镜像**（如存在）：`工作区/style-line.md`（用户对写法的原话汇总；项目里没有这份文件就记一句「用户还没提过风格意见」，**别把这一节跳过**）。

## 铁律（与另外两份审计模板同款，一条都不许打折）

- **上下文干净**：从零读上面列的每一份文件。你不知道「这本书是怎么造的」——不看建造日志、不看造书过程对话。
- **只报告、不改文件**：不要动工作区任何正文文件。**你唯一的产出是 `工作区/audit-cross.md`**（下面那份落盘契约）。
- **每条结论给证据**：**文件 / 章 / 位置 / 原文**。「第 3 章有问题」**不算点名**——写不出具体是哪一处，
  等于把查不动的活推回给主 agent。点名不到条目级的条目一律打回重做，不许当作一条意见收下
  （形状同 `audit-and-testing.md §10.b`）。
- **工具纪律（跨平台）**：文件 I/O 用文件工具（read / write / edit / glob / grep），shell 只留给真需要 shell 的
  场景且用前说明理由；规则对 Windows / macOS / Linux 完全一致，不点名单一 shell 名。
  单一事实源 `audit-and-testing.md §九 工具纪律`（**别处不另写一份**）。
- **完整报告在最终消息返回、不中途停**：不要读几章就回一句「我去核对」。
- **规模退化**：这本书只有一两章时不必走完整套派工——直接从零读那一两章＋三份约束件，按下面五节逐项
  核完、写完 `工作区/audit-cross.md` 即可。（判据不会假装有并发表：**五项逐项有交代**这一条无论几章都在。）

## 五项核对判定表

**这一节是五项判定词与判定口径的唯一起处。** 派发说明、方法论文档（`audit-and-testing.md` §十·第二轮）、
机器的拒收文案、造书模式人设都只引它；机器验货也从**这一节**解析判定词
（`src/workflow/cross-audit.js` 的 `crossAuditItemLabels()`）——所以**改判定词改这里一处**。
⚠️ 这一节原名「四项核对判定表」——自票 `reader-cognition-boundary-build/08` 起加了第五项「边界越界」，标题随之改名；旧文里引用旧名的地方按本节读。

| # | 判定词 | 判定口径（人读） |
| --- | --- | --- |
| 1 | 跨章事实一致性 | 同一个事实对象在全书各处只有一个说法：贯穿案例的数字、人名、设定、计数、时间线与因果顺序，前章说先发生 X，后章不能说先发生 Y；与 `outline.md` / `knowledge-map.json` 声明的归属对得上。 |
| 2 | 术语统一 | 同一概念全书一个说法（含译名、别名、符号）；各章的命名与写作规范的术语口径一致；统一过的地方**没有残留**（术语统一最常见的失败是只改了正文、没改表格与章末小结）。 |
| 3 | 交叉引用不悬空 | 正文里「见第 X 章」「前面讲过」「见卡 X.Y」「附录 X」指向的内容**真的存在**（以 `outline.md` 的章为准）；前向引用只到大纲承诺的粒度，没有编造未写章节的具体数字／结论／例题。 |
| 4 | 知识递进链 | 后章依赖的前置概念，前章真的讲过（不是只出现过名字）；`knowledge-map.json` 的知识点归属与正文实际讲到的位置对得上；术语与判据在书内**先讲后用**，没有倒着依赖。**逐条核下面「逐边清单（机器现算）」那一节的每一条**（跨章 ＋ 章内都在，⛔ 不是抽查可疑的那几条）；清单里带 `⚠️ 章序倒置` 的行就是「倒着依赖」的实证。判「通过」时，交代行必须**逐字照抄**「本书实际值」块里那一行（数就是机器现算的，机器会拿它跟自己算的逐数对账）。 |
| 5 | 边界越界 | 正文**明讲了**下列三档之一：① 读者已声明会的知识点（下沿以下；事实源＝剔除记录里 `reason＝已经会` 的那几条 ＋ 下沿）／② 读者已授权「做不到也没关系」的那几件（授权砍掉；事实源＝**目标声明**里那一格，票 `06` 的旧名「上沿声明」按 `ADR-0042` 后果 5 读作目标声明）／③ 超出**这本书能教到的知识范围**的内容（事实源＝上沿：图内 `reason＝不需要` 的那批卡 ∨ 图外）。每档出一句人可读的话并**点名到章**。⚠️ 候选面把话说小：① 卡一级机器能先算，但只证「这张卡被划了」；③ 只有一半（①能算；②图外仍只能 AI 判语义）；② 机器不能先算（⛔ 机器不代人做「目标 → 卡」的映射）。⛔ **不是阈值**：不设字数／条数闸。结论**只点名、由人裁**（⛔ 不派修复小助手自动改、⛔ 不进用户意见队）。 |

## 逐边清单（机器现算）

**这一节是「知识递进链」那一项的核对底账**，随派单由机器**逐边现算**（这本书的图长什么样由它告诉你，
你手上不需要另一份）：只列 `prereq` 边，**跨章 ＋ 章内都在**，⛔ 不是「只列看着可疑的那几条」——
只列可疑的等于把「真的讲过没有」退回散文。

每行四样：两端卡名 ／ 两端**各被哪一章认领** ／ **章序关系**（跨章给章序；同章给 `points` 数组下标
的章内序）／ 两端**位置索引**（哪份材料的哪一段）。**章序倒置的排在最前并带 `⚠️ 章序倒置` 标记**
（前置那条被认领的章序**晚于**依赖它的那条——那正是「倒着依赖」那件事）。

{{逐边清单}}

清单里凡报「（人已划掉）」的卡（**有没有章认领都算**：没人认领是「未被任何章认领（人已划掉）」，
有人认领是「第 N 章认领（人已划掉）」）：人对它下过「不讲」的裁决，**如实把这句记下来**，
⛔ 不剪它的边、不替人把下游一起划、也不提前拦——它是**如实报**的对象，不是你要修的问题。

⚠️ **条数对账**：判「通过」时，上面第 4 项那一节的交代行必须**逐字照抄**「本书实际值 · 机器代填」
块里那一行（形如 `已核，未见——逐边清单 N 条全核（跨章 X／章内 Y），无倒置、无「只出现名字」`）。
机器会从那行里解析 N／X／Y，与它**自己现算的**逐数对账，并要求 `N = X + Y`；「无倒置」也机器判。
⛔ 别自己数、别改一个数：对不上就 400 并逐数点名。清单里有 `⚠️ 章序倒置` 的行时，把那一项判
**不通过**并逐条点名那几条（点名要指到卡名与章）。

## 落盘契约：`工作区/audit-cross.md`（报告人自落，机器逐项验）

**五项各一节**，小标题含上表的判定词（小节顺序照上表；节内先写结论行，再写交代）：

```markdown
# 合并前跨章审计

审计对象：全书 {{N}} 章 + outline + knowledge-map + 写作规范
审计方式：跨章审计小助手（干净上下文，从零读）

## 1. 跨章事实一致性
结论：通过
已核，未见——数字、人名、时间线全书一致

## 2. 术语统一
结论：不通过
- P1｜第 3 章《整式》把「多项式」写成「多项式式」，与第 1 章不一致。位置：第 3 章第 2 段；原文：「…」
- P2｜第 2 章表格里仍用旧译名「向量」，正文已统一。位置：第 2 章「常见误区」表第 3 行；原文：「…」

## 3. 交叉引用不悬空
结论：通过
已核，未见——「见第 X 章」指向的章都在大纲里，前向引用没越过承诺粒度

## 4. 知识递进链
结论：通过
已核，未见——逐边清单 N 条全核（跨章 X／章内 Y），无倒置、无「只出现名字」
（N／X／Y 逐字照抄「本书实际值 · 机器代填」块里那一行；⛔ 别自己数、别改一个数）

## 5. 边界越界
结论：通过
已核，未见——下沿以下、授权砍掉、超出这本书能教到的知识范围三档逐章对过，未见越界处
```

机器只认这四条**可解析的形状**（`src/workflow/cross-audit.js`，它只断接线与形状，**不判断结论对错**、
也不判断「是不是只出现名字」）：

1. 每项有一个**小标题含该项判定词**；
2. 那一节里有一行 **`结论：通过`** 或 **`结论：不通过`**；
3. 判「通过」必须写 `已核，未见`——**无问题也要交代**，否则「没查」与「查了没问题」在盘上长得一样；
   判「不通过」必须**至少一条点名条目**（每条一行「`- …`」，指到章／位置／原文）。
4. 「知识递进链」判「通过」时，交代行还必须写成上面那一行逐边清单的**条数对账句**
   （`已核，未见——逐边清单 N 条全核（跨章 X／章内 Y），…`）：机器解析 N／X／Y 与**自己现算的**
   逐数对账、要求 `N = X + Y`，并核「无倒置」那一句。⚠️ 它解析的是**报告的写法**——
   **不证明审计真读了原文**（那是真机层）；判「不通过」那一支没有条数要求。

缺任何一项，机器在 `stage-submit merge` 时 400 拒收，并**点名缺哪一项、为什么**。

⚠️ **第五项（边界越界）只点名、由人裁**：它的结论同样落这份报告，由主笔在**汇总裁决**里**单列一栏**
（「哪几条要改、哪几条留给你定」）；**改与不改由人在读到点名之后决定**，决定之后才走既有的修订派发。
⛔ 不写进 `meta.pendingReviews`（那条队装的是**用户自己**的抽查意见，写进去就是冒充）；
⛔ 不派修复小助手自动改——其余项是「写错了」，越界是「**该不该写**」。

### 严重度与回灌三件套（细目落盘 ＋ 最终回复 ≤N ＋ 回灌结构）

- **严重度**：每条点名标 P0 必改 / P1 应改 / P2 可改，并给证据（文件 / 章 / 位置 / 原文）；给不出证据的标「未核实」。
- **① 细目落盘（报告人自落）**：五项核对的完整交代写进 `工作区/audit-cross.md`（契约见上面「落盘契约」一节），
  回复里**只留指针、不抄全文**——主 agent 要看细节自己回读那份文件。
- **② 最终回复 ≤N**：**这一档的 N 以 `audit-and-testing.md §九`「回灌三件套 · 单一事实源」那张逐类一档表为准**
  （「跨章审计」那一行），**本模板有意不写 ≤N 字面**——那张表已经由 `test-subagent-report-budget.mjs` 的
  `judgeSingleSource` 逐行钉住，这里再抄一个数字就是**第二份会漂的预算档**，而 ADR-0030 决策 4 治的正是这个病。
  压预算压的是「把完整逐条证据也抄进回复」，不是压证据本身；压不进去就把点名挑最重的几条写，**证据不许省**。
- **③ 回灌结构＝结论 ＋ 条目级点名 ＋ 落盘路径**（三样之外不收别的）：
  1. **结论**：五项各一句（通过／不通过）；
  2. **条目级点名**：逐条给出**条目级**的点名（严重度 ＋ 章／位置 ＋ 原文引一句），
     「第 3 章有问题」**不算点名**；
  3. **落盘路径**：`工作区/audit-cross.md`。
- **主 agent 的汇总裁决由它自己追加**（小 edit，不整份重写）：哪几条要改、哪几条判为误判，写在报告末尾。
  **第五项（边界越界）的点名在裁决里*单列一栏***（「哪几条要改、哪几条留给你定」）——改与不改由人裁，⛔ 不派修复小助手自动改。

## 主 agent 收到报告后（协调者形态 · ADR-0030 决策 2）

- **主 agent 不读章正文**：它只收这份报告。核实是写这份报告的助手自己的活（同一读法见 `audit-and-testing.md §6.2` 终检那一层的例外口径）。
- **按点名条目逐条派修复小助手改**（派发形状见下面「修复小助手」一节；**第五项（边界越界）不在此列**——越界是取舍、只点名由人裁）；**主 agent 自己不动章正文**。
- **汇总裁决追加**进 `工作区/audit-cross.md`（哪几条要改、哪几条判为误判），再写前言、`stage-submit`。
- **重复审计**：merge 被深改或用户驳回后重跑时，**优先 `send_message` 唤醒原来那个跨章审计小助手**
  （用 `list_agents` 按「跨章审计」这个 label 召回），召不回才新派——同一份审计重新读一遍全书很贵。

## 修复小助手（点名条目逐条改的派发形状）

- 一条点名 = 一次派发（或同一路里逐条），**只改点名的条目**，不通读全书、不顺手重写别的章。
- ⛔ **第五项（边界越界）的点名不走这一节**：它是取舍，等人在汇总裁决里点过头才可能进修订派发。
