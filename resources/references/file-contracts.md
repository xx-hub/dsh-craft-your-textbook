# 契约必答问题清单（写作规范 + 章节骨架 + 源定位）

> **本文件是 SKILL.md Iron Law 1（先出设计再写正文）的定稿判据**：
> - 设计期五步设计产出的每一件契约产物都必须答完本文对应的所有必答问题。
> - 设计期三个停点（三次拍板）＋ 章节安排未全部通过 = 契约未定稿 = 禁止写任何章正文（Iron Law 1）。
> - 写作规范答 §防螺旋铁律（I9）= 约束设计定稿后不得加章/附录/机制板块。
> - 缺答或未过停点即返工回到设计期，不存在"先开写正文后补契约"的灰色通道。

> **这份共用方法论也被上游 skill 产品原样使用，两边的产物文件名不一样。**
> 下面一律用**产物角色名**说话（写作规范 / 章节骨架 / 源材料索引 / 风格与语法）；
> 本仓工作台的实际路径以 `mechanism.md` §产物路径 为准——写作规范＝`工作区/style-spec.md`、
> 章节骨架＝`工作区/outline.md`、源材料索引＝`工作区/explore.md` ＋ `工作区/knowledge-map.json`。
> **任何一处只写一边的文件名，审计就会去查一个你项目里根本不存在的文件。**

> 下文「写作规范」两节（契约与铁律 / 风格与语法）在本仓是**同一份 `工作区/style-spec.md` 的两节**——两半都必须答完。

> Agent 产出契约产物时，每一件必须回答完下面对应的所有问题。
> 契约强制"必须回答什么"，不预设"答案是什么"——答案由 Agent 按本书分析得出。
> 完整设计流程见 SKILL.md。

> **设计期那三次拍板各有自己的形状节**：`学习目标与难点`＝第 1 次拍板、`教学方法与板块`＝第 2 次拍板、
> `章节骨架（大纲与架构）`＝第 3 次拍板。前两节只服务那两关；第三节同时也是写作期的大纲契约
> （所以它在下面与写作规范并列）。三关的落点都是**那一关的提案**（`工作区/方案/关卡N-vM.md` 的正文），
> 拍定之后才落成写作规范。⛔ 别把设计期的答案抄成写作规范的定稿、也别反过来拿写作规范的措辞当这一关的答案。

## 学习目标与难点

（**落点**：关卡① 的提案（`工作区/方案/关卡1-vM.md`）与站 3 的结论件；拍定后落进 `工作区/style-spec.md`
的「本书定位」与 `工作区/outline.md` 的知识链主线。）

1. **目标复核表**：把上游已经拍定的 3–5 条学习目标逐条过一遍，每条标一个处置——**保留／改写／新增／删掉**；
   改写与新增要写清改成什么、为什么；删掉要写清删了之后哪条目标承接它的位置。
2. **这本书主要怎么学**：一句话说清读者的使用方式（顺序讲／按需检索／跟着案例做），这一条由用户在卡片上拍定。
3. **难点清单**：本书真正的难点是哪几处？逐条写清「难在哪」——是概念抽象、是材料缺页、是读者带着错误的前见，
   还是几个概念彼此纠缠。⛔ 不写「本章较难」这种没有落点的话。
4. **目标 ↔ 难点对应**：每条难点挂在哪条目标上；哪条难点必须先解决（后面的内容压着它）；哪条可以放到章末教学区再收。
5. **这次要动的三条**：新增哪一条、把哪一条改写成什么、删掉哪一条——随本关提案一起交给用户拍板
   （改动要显式落一笔，不许「顺手改」。）

## 教学方法与板块

（**落点**：关卡② 的提案（`工作区/方案/关卡2-vM.md`）；拍定后落进 `工作区/style-spec.md` 的
「章内板块语法」与「风格与语法」两节。）

1. **模式选型**：考虑过哪些教学模式、拒绝了哪些、为什么；选中的每个模式对应本书哪个教学问题。
   （本关只定**选型与理由**；落笔时的完整语法——长度／人称／位置——在下面「风格与语法」那一节答。）
2. **每章板块结构**：必含板块／循环单元／可选板块／叙事约定／章末教学区形态，逐类给出板块名（板块名要能
   被写作小助手在章里逐字照用）。
3. **板块 ↔ 难点对应**：关卡① 列出的每条难点由哪个板块兑现；哪个板块只是锦上添花（写清为什么留着）。
4. **深度四维承诺**：机理／原理、脉络／争议、边界／反例、专家视角／精度各定「深／中／浅」，
   声明「浅」要写明理由（判定问题见 `references/depth.md`）。
5. **不许现在定的**：具体措辞、句式、篇幅数字——那是写作规范与逐章交办的事；本关定了它们就等于
   在用户拍板之前把定稿写死了。

## 写作规范 · 契约与铁律

（**落点**：`工作区/style-spec.md` 的一节。）

正文必答问题：

1. **本书定位**：一句话说清这本书是什么、给谁用。路线已在 YAML frontmatter 声明，此处不重复。
2. **防幻觉铁律**：本书最危险的断言类型是什么（定义/公式/偏好判断/历史事实/代码）？回源到哪？追不到源怎么降级？
3. **读者意识声明**：本书第一读者是谁（AI 老师/人类读者）？写每块前问什么问题？
4. **章内板块语法**：从设计期的板块设计搬过来——必含板块/循环单元/可选板块/叙事约定/章末教学区形态。
5. **章末教学区规范**：章末教学区的板块结构、长度、格式要求。
6. **写作纪律**：一个 agent 写几章？并行度？篇幅约束（不讲数字——唯一约束是"讲完、讲透该章该覆盖的知识"。短不凑字，长不灌水）？明确排除项（不写什么）？
7. **frontmatter schema**：需要章级 yaml 则定义字段+校验规则；不需要则显式声明"本书无章级 frontmatter"。
8. **AI 老师使用方式**：顺序讲/地基章先吃透/按需检索？
9. **防螺旋铁律（I9）**：定稿后加章/附录/机制级板块的回炉规则。
10. **脚手架标题列表**：交付前拆脚手架用——本书写作过程中会用哪些元数据板块标题（如"## 自检清单""## 写作笔记"）。设计期只列已知/可预判的标题；写作过程中新增的元数据板块标题，由写作 agent 在对应章节同步追加进写作规范此列表，保证交付前拆除时不遗漏。

## 章节骨架（大纲与架构）

（**落点**：`工作区/outline.md` ＋ 关卡③ 提案。）

1. **知识链主线**：一句话说清全书推理主线。
2. **卷/部划分**：怎么分组、为什么这样分。
3. **逐章骨架表**：章号/标题/类型（Agent 自定的类型名，如 eco_task/foundation/agile_practice/exam_strategy；逐章交办用「章号/标题/类型/知识链位置/锚定知识点」五行）/在知识链中的位置/锚定的知识点。
   - ⚠️ **第 5 列统一是「锚定的知识点」**：本仓知识点清单来自 `工作区/knowledge-map.json（知识地图）` 的 `knowledgePoints[]`，逐章交办（`points[]`）与写作小助手的打钩都以它为准。**无源（从零造）的书没有知识点清单**，那时这一列写「锚定的源任务或概念」，其余各列不变。
4. **特殊功能章**（如有）：地基章/总结章/策略章——为什么不能并入正常章。
5. **跨章引用机制**：本书用什么形式做知识回扣（行内回溯/连接表/主题低音线）——说清具体形式。
6. **附录汇编策略**：从哪些章末板块自动汇编成哪些附录。
7. **贯穿案例/主角约定**（如选了 narrative 卡）：案例/主角是什么，边界在哪（如"不写人物情感弧线"）。
8. **成品书 loader 指令内容**（human-readable 路线，`工作区/book.md`）：写给 AI 老师的装配说明（"正文 prose 是素材库用自己的话重组教学；章末教学区照问题链走"），如需针对本书定制措辞就改这段说明本身。pure-blueprint 路线不注入 loader。
   - ⚠️ 这段说明**落在成品书的装配环节**（本仓改书夹里 `<!-- loader:begin -->` 那一区）——**必答的是这段措辞的内容，不是脚本参数。**

## 风格与语法

（**落点**：`工作区/style-spec.md` 的另一节。）

1. **模式选型说明**：两个强制问题回答——考虑过哪些模式、拒绝了哪些、为什么拒绝？所选每个模式对应本书哪个教学问题？
2. **章内板块语法完整版**：必含/循环/可选板块，每个板块的写作要求、长度、人称、位置。
3. **情境钩子写法**：长度/人称/必含元素/挂靠贯穿案例的规则。
4. **正文语言风格**：正式程度/术语处理（原文/翻译/双语）/本书特有禁用词（不是全局硬编码）。
5. **量化参考密度**：每章小节数/Definition 数/misconception 数/习题数——参考非铁律，最佳范例章后回填实测。
6. **最佳范例章写作惯例区**：最佳范例章通过审计后回填——实测密度/踩过的坑/确认不套用的视角。
7. **深度四维承诺**：本书四维深度各兑现到什么程度？填表——
   | 维度 | 目标（深/中/浅） | 用什么板块/写法兑现 |
   |---|---|---|
   | 机理/原理 | 中 | 例：### Definition 后加"为什么"段 |
   | 脉络/争议 | 浅（理由：入门书不展开学科史） | 例：不展开学派争议 |
   | 边界/反例 | 深 | 例：misconception 卡全面展开 |
   | 专家视角/精度 | 中 | 例：judgment-card 的 why-not |
   规则：默认"中"为底线；声明"浅"必须写明理由，并经第 2 次拍板（教学方法与板块）认可。判定问题见 `references/depth.md`。

## 源材料索引与源定位（有源场景）

（**落点**：`工作区/explore.md` ＋ `工作区/knowledge-map.json`。）

1. **源文件简码表**：简码/路径/定位/权威层级。
2. **全书通用锚点**：跨章共享的源定位（如公式汇总表/原则全文位置）。
3. **分章源映射**：每章四要素——
   - ① 章→源文件行号映射
   - ② 预抽关键条目
   - ③ 高频陷阱/偏好预判
   - ④ 写作惯例（最佳范例章后回填）
4. **可信度声明**：建索引时实际探查了什么、发现了什么问题（如"XX 笔记是 OCR 碎片，非完整骨架"）。

无源（从零造）不建此文件，在写作规范里声明知识密度自评结果 + 深度可达自评结果 + L5 强制路径。
