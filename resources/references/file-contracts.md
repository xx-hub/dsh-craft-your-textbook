## 写作规范 · 契约与铁律

（**落点**：skill 侧 `META.md` / 本仓 `work/style-spec.md` 的一节。）

正文必答问题：

1. **本书定位**：一句话说清这本书是什么、给谁用。路线已在 YAML frontmatter 声明，此处不重复。
2. **防幻觉铁律**：本书最危险的断言类型是什么（定义/公式/偏好判断/历史事实/代码）？回源到哪？追不到源怎么降级？
3. **读者意识声明**：本书第一读者是谁（AI 老师/人类读者）？写每块前问什么问题？
4. **章内板块语法**：从 Phase 3.3 搬过来——必含板块/循环单元/可选板块/叙事约定/章末教学区形态。
5. **章末教学区规范**：章末教学区的板块结构、长度、格式要求。
6. **写作纪律**：一个 agent 写几章？并行度？篇幅约束（不讲数字——唯一约束是"讲完、讲透该章该覆盖的知识"。短不凑字，长不灌水）？明确排除项（不写什么）？
7. **frontmatter schema**：需要章级 yaml 则定义字段+校验规则；不需要则显式声明"本书无章级 frontmatter"。
8. **AI 老师使用方式**：顺序讲/地基章先吃透/按需检索？
9. **防螺旋铁律（I9）**：定稿后加章/附录/机制级板块的回炉规则。
10. **脚手架标题列表**：交付前拆脚手架用——本书写作过程中会用哪些元数据板块标题（如"## 自检清单""## 写作笔记"）。Phase 3.5 只列已知/可预判的标题；写作过程中新增的元数据板块标题，由写作 agent 在对应章节同步追加进写作规范此列表，保证交付前拆除时不遗漏。

## 章节骨架（大纲与架构）

（**落点**：skill 侧 `OUTLINE.md` / 本仓 `work/outline.md` ＋ 关卡③ 提案。）

1. **知识链主线**：一句话说清全书推理主线。
2. **卷/部划分**：怎么分组、为什么这样分。
3. **逐章骨架表**：章号/标题/类型（Agent 自定的类型名，如 eco_task/foundation/agile_practice/exam_strategy；本仓逐章交办用「章号/标题/类型/知识链位置/锚定知识点」五行）/在知识链中的位置/锚定的知识点。
   - ⚠️ **第 5 列统一是「锚定的知识点」**：本仓知识点清单来自 `work/knowledge-map.json` 的 `knowledgePoints[]`，逐章交办（`points[]`）与写作小助手的打钩都以它为准。**无源（Mode A）书没有知识点清单**，那时这一列写「锚定的源任务或概念」，其余各列不变。
4. **特殊功能章**（如有）：地基章/总结章/策略章——为什么不能并入正常章。
5. **跨章引用机制**：本书用什么形式做知识回扣（行内回溯/连接表/主题低音线）——说清具体形式。
6. **附录汇编策略**：从哪些章末板块自动汇编成哪些附录。
7. **贯穿案例/主角约定**（如选了 narrative 卡）：案例/主角是什么，边界在哪（如"不写人物情感弧线"）。
8. **BOOK.md loader 指令内容**（human-readable 路线）：写给 AI 老师的装配说明（"正文 prose 是素材库用自己的话重组教学；章末教学区照问题链走"），如需针对本书定制措辞就改这段说明本身。pure-blueprint 路线不注入 loader。
   - ⚠️ 这段说明**落在成品书的装配环节**，各产品的落地方式不同（skill 侧改**装配脚本** `merge_book.py` 的 `LOADER_TEMPLATE`；本仓无脚本，改书夹里 `<!-- loader:begin -->` 那一区）——**必答的是这段措辞的内容，不是脚本参数。**

## 风格与语法

（**落点**：skill 侧 `style-spec.md` / 本仓 `work/style-spec.md` 的另一节。）

1. **模式选型说明**：两个强制问题回答——考虑过哪些模式、拒绝了哪些、为什么拒绝？所选每个模式对应本书哪个教学问题？
2. **章内板块语法完整版**：必含/循环/可选板块，每个板块的写作要求、长度、人称、位置。
3. **情境钩子写法**：长度/人称/必含元素/挂靠贯穿案例的规则。
4. **正文语言风格**：正式程度/术语处理（原文/翻译/双语）/本书特有禁用词（不是全局硬编码）。
5. **量化参考密度**：每章小节数/Definition 数/misconception 数/习题数——参考非铁律，最佳范例章后回填实测。
6. **最佳范例章写作惯例区**：Phase 4 通过后回填——实测密度/踩过的坑/确认不套用的视角。
7. **深度四维承诺**：本书四维深度各兑现到什么程度？填表——
   | 维度 | 目标（深/中/浅） | 用什么板块/写法兑现 |
   |---|---|---|
   | 机理/原理 | 中 | 例：### Definition 后加"为什么"段 |
   | 脉络/争议 | 浅（理由：入门书不展开学科史） | 例：不展开学派争议 |
   | 边界/反例 | 深 | 例：misconception 卡全面展开 |
   | 专家视角/精度 | 中 | 例：judgment-card 的 why-not |
   规则：默认"中"为底线；声明"浅"必须写明理由，并经用户确认关卡②（Phase 3.3）认可。判定问题见 `references/depth.md`。

## 源材料索引与源定位（有源场景）

（**落点**：skill 侧 `源材料索引.md` / 本仓 `work/explore.md` ＋ `work/knowledge-map.json`。）

1. **源文件简码表**：简码/路径/定位/权威层级。
2. **全书通用锚点**：跨章共享的源定位（如公式汇总表/原则全文位置）。
3. **分章源映射**：每章四要素——
   - ① 章→源文件行号映射
   - ② 预抽关键条目
   - ③ 高频陷阱/偏好预判
   - ④ 写作惯例（最佳范例章后回填）
4. **可信度声明**：建索引时实际探查了什么、发现了什么问题（如"XX 笔记是 OCR 碎片，非完整骨架"）。

Mode A（无源）不建此文件，在写作规范里声明知识密度自评结果 + 深度可达自评结果 + L5 强制路径。
