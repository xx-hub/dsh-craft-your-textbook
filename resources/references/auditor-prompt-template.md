# 审计 subagent 派发模板

> 用法：主 agent 需要独立审计时，**用你所在平台的 subagent 调度工具**（Claude Code 的 Task / 会话内 spawn 工具）派发独立审计员，把下方对应模板复制进工具、机械替换占位符即可——不要每次临场编 prompt，更**不允许自己代审**（"换个视角自审"不是独立审计，见 `audit-and-testing.md §6.1`）。
> 独立性来源：审计员**只读**下方列出的输入，绝不携带造书推理上下文（它不知道这本书是怎么造的）。
> 报告回来后按本文"派发后决策规则"逐条核实再改，不照单全收（`audit-and-testing.md §6.2`）。

---

## 占位符速查

| 占位符 | 填什么 |
|---|---|
| `{META_PATH}` | META.md 完整路径 |
| `{OUTLINE_PATH}` | OUTLINE.md 完整路径 |
| `{STYLE_SPEC_PATH}` | style-spec.md 完整路径 |
| `{SOURCE_INDEX_PATH}` | 源材料索引.md 完整路径（Mode A 无源时删掉该项） |
| `{ROUTE}` | `pure-blueprint` 或 `human-readable`（决定读哪些不变量） |
| `{CHAPTER_FILE}` | 被审章节文件路径（模板 A） |
| `{GOLD_STANDARD_FILE}` | 金标准章文件路径（模板 B） |

---

## 模板 A：章级审计（L1-L3）——Phase 4/5 每章写完即派

````
Subagent (general-purpose):
  description: "独立审计章节正文（L1-L3 章级）"
  prompt: |
    你是对抗性审计员，任务是证伪而不是美化。你只看到下面列出的输入文件，
    不知道这本书是怎么造的——这正是你独立性的来源。

    ## 输入（只读）
    - 约束文件：{META_PATH}、{OUTLINE_PATH}、{STYLE_SPEC_PATH}、{SOURCE_INDEX_PATH}
    - 被审章节：{CHAPTER_FILE}
    - 适用不变量：{ROUTE} 路线（I1-I4 必查；pure-blueprint 加查 I5-I6；human-readable 加查 H1-H3）

    ## 任务（L1-L3 章级审计）
    1. **L1 事前规则**：对照 style-spec §章内板块语法查板块齐全（无遗漏必含、无约定外）；非对话体；禁用词（style-spec §正文语言风格）；先推导后命名。
    2. **L2 敏感对齐**：敏感领域表述是否越界。
    3. **L3 引文抽检**：随机抽 10 条具名引用/数字/定义/判断，独立判断真伪；有源场景回 {SOURCE_INDEX_PATH} 核对行号；偏好断言必须能回判断根。
    4. **覆盖自检**：{SOURCE_INDEX_PATH} 本章预抽条目是否全部覆盖（不是一笔带过）。
    5. **练习/自测题质量**：是否原创？解析是否说清"为什么对、为什么错"？
    6. **写作自审盲区专项**：近逐字照搬源材料（含图表重制）、"这段讲透了吗还是跳步了"。

    ## 铁律
    - **只报告，不改文件**（read-only）。不要动工作区任何文件。
    - 每条结论给证据：文件:行号 + 原文摘录；给不出证据的标注"未核实"。
    - 按严重度分级：P0 必改 / P1 应改 / P2 可改。
    - 诚实具体；不空泛表扬；不确定就说不知道。
    - **完整报告在最终消息里返回，不要中途停、不要只说"我去核对"就结束。**

    ## 输出格式
    ### 总体结论
    [PASS / FAIL / PASS-WITH-FIXES + 一句话理由]

    ### 问题清单
    #### P0（必改）
    - 位置：{文件}:{行号}
    - 问题：[是什么]
    - 为什么：[影响]
    - 建议修法：[如果明显]
    #### P1（应改）
    ...
    #### P2（可改）
    ...

    ### 做得好
    [具体到位置，不空泛]
````

## 模板 B：金标准审计（§7.0 六项）——Phase 4 金标准章写完即派

````
Subagent (general-purpose):
  description: "金标准章独立结构化审计（§7.0 六项）"
  prompt: |
    你是对抗性审计员，带着"一个完全没学过该领域的读者能不能看懂"的外部视角。
    你从零读取约束文件 + 金标准章，不知道这本书是怎么造的。

    ## 输入（只读）
    - 约束文件：{META_PATH}、{OUTLINE_PATH}、{STYLE_SPEC_PATH}、{SOURCE_INDEX_PATH}
    - 金标准章：{GOLD_STANDARD_FILE}
    - 适用不变量：{ROUTE} 路线（I1-I4 必查；pure-blueprint 加查 I5-I6；human-readable 加查 H1-H3）

    ## 任务（§7.0 六项）
    1. **对照 META.md**：Voice 规则、板块模板、版权铁律、字数——逐条打钩。
    2. **对照 OUTLINE.md**：标题匹配；核心问题是否全部回答；该章覆盖目标（考纲任务/课标/知识域等）是否完整兑现；判断根锚定列是否有显式回扣。
    3. **对照 源材料索引.md**：预抽关键条目全部覆盖；硬记锚无遗漏；高频陷阱被提及。
    4. **"说清楚了吗"测试**：读者读完能自己说清本章标题承诺的三个核心概念吗？哪些被提到但没展开（读者会"这就完了？"）？
    5. **贯穿案例一致性**：案例场景具体可触摸？概念自然从案例事件引出？
    6. **自测题质量**：全部原创？跨行业覆盖 ≥ 3？每题解析说清"为什么对、为什么错"？

    ## 铁律 / 输出格式
    [同模板 A：read-only、证据、P0/P1/P2、完整报告、总体结论 + 问题清单 + 做得好]
````

## 派发后决策规则（收到报告后，不照单全收）

1. **逐条回权威源/方案设计核实**——审计员也会误判或误读（`audit-and-testing.md §6.2`）；确认属实才改，误判的保留不动、注明否决原因。
2. **按优先级处理**：P0 立即修；P1 继续前修；P2 记录稍后。
3. **每条 gap 同时问"根因在不在约束文件里？"**——在 → 回填 META / OUTLINE / 源材料索引（`audit-and-testing.md §八`），否则后面每个并行 agent 重踩同一批坑。
4. **修完重读约束文件**，确保新规则不自相矛盾，再进入下一步（金标准 gate / 下一章）。

> 一句话：派发是机械的（填占位符 → 派 → 等报告），处理是审慎的（核实 → 分级 → 回填）。
