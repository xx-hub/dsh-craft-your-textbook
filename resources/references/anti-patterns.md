> **与 SKILL.md 的分工**：
> - SKILL.md 的 **Rationalization Red Flags** 是**流程级**反模式索引（"我先快速看一眼源""差不多了先开写"这类念头 = STOP）。
> - 本文件是**详细反模式速查**（内容级 + 工程陷阱），下面"流程级"一节的具体条目 = SKILL.md 三条 Iron Law 的违例清单——"无金标准节就并行写多节"违反 Iron Law 2，"跳过拆脚手架 + 质量门"违反 Iron Law 3，"Phase 3 没定稿就开写正文"违反 Iron Law 1。

## 纪律级：红旗自检（Red Flags - STOP）

> 本 skill 最易在压力下破功的 6 条纪律。**当你发现自己正在想下列话 → STOP，回到规则。**
> 借口表条目来自真实压力测试（`tests/` 场景）中 agent 的逐字供述；维护流程见 `references/skill-maintenance.md`。

### ① 定路线不替用户默认
**红旗——正在想这些 → STOP**：
- "用户说'你看着办'就是授权了"
- "反正 99% 会同意 pure-blueprint，问不问一样"
- "猜错了反正还早，改起来不难"

| 借口 | 真相 |
|---|---|
| "你看着办"就是授权 | 你无法替用户委托一个他不知道存在的决定——"推荐"≠"替你决定"，必须呈现两选项等确认 |
| 推荐默认路线不算违背 | 跳过确认 = 违反 Trigger Contract |
| 反正会同意，问不问一样 | 路线错 = Phase 3 整轮重做；30 秒确认远低于整本书重做成本 |
| 改起来不难 | 路线错了不是换措辞，是整本书形态重做 |

### ② 最佳范例章先行（I7）
**红旗——正在想这些 → STOP**：
- "设计已经很扎实了，不用先写一章最佳范例章"
- "用户是老板，他说并行就并行"
- "先并行写几章'试探'风格稳不稳"

| 借口 | 真相 |
|---|---|
| 设计扎实就不用最佳范例章 | style-spec 的写作惯例区只能从真写一章 + 真审计回填——设计阶段物理上不可能有 |
| 用户要并行 | 用户要的是"一周交好书"；范例章是全项目最高杠杆时间，不是延期 |
| 3 章试探比较保守 | 没有范例章做锚，3 个 agent 照样各自漂，只是把漂移缩了规模、白烧时间 |

### ③ 审计独立性（§6.1）
**红旗——正在想这些 → STOP**：
- "我自审两遍了，不用再起 subagent"
- "我就是最懂这章的人"
- "让同事扫一眼就算独立审计了"
- "自审通过写进报告，流程就闭环了"

| 借口 | 真相 |
|---|---|
| 我读两遍就没问题 | 写作者对自己推导失明——"我读到的"≠"读者看到的" |
| 我最懂这章 | 你懂的是建造推理，丢失的是外部视角（新手读者能不能看懂） |
| 同事扫一眼 = 独立审计 | 伪独立：带共同上下文、非结构化，是"看起来像走流程"的表演 |
| 自审=审计完成 | 直接违反 §6.1；审计员必须不知道建造时的推理 |

### ④ 防螺旋（I9）
**红旗——正在想这些 → STOP**：
- "加一章很轻率，先直接插进去"
- "塞进附录就不算加章了"
- "用户说要加章，就可以不改下游"

| 借口 | 真相 |
|---|---|
| 直接插一行就行 | 新章没有板块语法、知识链位置、跨章回扣与源映射，跨章审计失去坐标系 |
| 塞附录绕开铁律 | 附录只承担汇总速查；用位置话术规避设计变更会破坏产物契约 |
| 用户要加就直接改 | 用户主动变更合法，但定稿后必须走「定点修改（深改）」并重做受影响下游，不能静默插入 |

### ⑤ 拆脚手架（I8）
**红旗——正在想这些 → STOP**：
- "AI 老师看不懂注释，不影响"
- "拆脚手架是洁癖不是必需"
- "先交付，明天白天再清理"
- "自检清单留着是资产"

| 借口 | 真相 |
|---|---|
| AI 老师看不懂 | 实战：某书 112 个标记让 AI 老师无法做对比——它只有这一本书，标记全是无参照噪音 |
| 洁癖不是必需 | I8 是不变量非偏好；拆完书里只剩"教什么 + 怎么教" |
| 明天再清理 | 事后清理比现在拆更贵（该例两轮清理删了 36,477 字符，-9.4%） |
| 留着是资产 | 把半成品当成品交付，AI 老师会尝试解读这些元数据 |

### ⑥ audit-backfill（§八）
**红旗——正在想这些 → STOP**：
- "修章就够了，回填太慢"
- "后面并行章我注意着点就行"
- "加一句注释就算回填了"

| 借口 | 真相 |
|---|---|
| 修章就够了 | 根因在约束文件 = 每个并行章重踩；修章 + 回填才防复发 |
| 我注意着点 | 不是机制是感觉——上下文一换就蒸发；规则写进 agent 必读的约束文件才是载体 |
| 注释算回填 | 注释无约束力；§8.1 判的是"规则够不够硬"，注释不是槽位 |

## 框架级
- ❌ 把蓝本当"给读者读的书"来写
- ❌ 开篇钩子写成"读者读到这里会想……"（读者根本不读）
- ❌ 通篇"用'你'贯穿"但不写清楚"你"指谁

## 诚实边界级
- ❌ 不诚实声明本书能力边界（如"本题库足够通过考试"但题量明显不够；"读完就能掌握"但内容明显不足）
- ❌ 假装速判脚本/练习能替代题库（PMP 60-90 题建不了真反射，要诚实说"示范思路，刷题量靠题库接力"）

## 拆脚手架级（最易犯）
- ❌ 最终产物留 `<!-- v2 新增 -->` 等版本标记
- ❌ 书里写"本单元新增了 X"（AI 老师没有旧版对比）
- ❌ 保留自检清单（造书者 QA 打勾，非教学内容）
- ❌ 保留版本记录（v1.0/v1.1 修订日志，非教学内容）
- ❌ "教师用书说……"直接暴露来源（应转成"本单元……"）
- ❌ "给人类教师读的"口吻残留（应转成"给 AI 老师的指令"）
- ❌ 附录里留"v2.0 增量"段落

## 架构级
- ❌ 教材目录直接当蓝本目录
- ❌ 章节锚定抽象概念而非具体对象
- ❌ 把知识点堆进附录当兜底（该在单元里讲清的，别推给附录——附录只做汇总速查，不承载首次讲解）

## 大纲级
- ❌ Phase 3 不充分分析源和目标就开写（跳过教学设计五步）
- ❌ 缺跨章引用机制
- ❌ Phase 3 没定稿就开写正文

## 写作级
- ❌ "本节课我们将学习……"
- ❌ 先定义再展开（应"先推导后命名"）
- ❌ 写死"老师说：……学生答：……"对话脚本

## 引文级（Mode A）
- ❌ 编造卷号页码 / 张冠李戴
- ❌ 一有犹豫仍强行具名引用

## 流程级
- ❌ 让写作 agent 审计自己
- ❌ 无金标准节就并行写多节
- ❌ **金标准章不做独立 subagent 审计**：写完金标准章就默认"差不多了"直接进并行铺章——写作 agent 已经沉浸在自己的推导逻辑里，看不出叙事断弧和覆盖缺口。必须起一个干净上下文的 subagent，从零读约束文件+章正文做结构化审计（见 `audit-and-testing.md §7.0`）
- ❌ **审计完只修章、不修约束文件**：审计暴露的问题有一半根因在 META/OUTLINE/源材料索引没写清楚。只修章不回填 = 后面每个并行 agent 重踩同一批坑（见 `audit-and-testing.md §八`）
- ❌ 跳过跨章审计（Phase 5.3）
- ❌ 应触发时跳过 L5 教学测试
- ❌ 期待一次成型
- ❌ 跳过拆脚手架 + 质量门（Phase 6）

## 工程陷阱
- **MinerU Token 泄漏**：❌ 绝不把 `mineru.net` 的 API Token 明文写进脚本（曾有项目把真 token 硬编码进 `01_pdf_to_md.py`，随仓库一起泄漏）。一律走 `MINERU_TOKEN` 环境变量；提交前 grep 一遍确保无明文密钥
- **忘了申请 apikey**：Phase 1 开跑前必须先让用户去 https://mineru.net 申请 API Token 并设好环境变量，否则脚本第一步就 401
- **后台任务丢输出**：`command | head -N` 会让 Windows Python 静默丢输出。用 `python -u` + 日志文件
- **长上下文 subagent 容易漂**：每个 subagent 只做一件事
- **大 PDF 处理**：MinerU API 200 页约几分钟；本地 `marker-pdf` 200 页约 40 min，`--disable-ocr` 提速；超大 PDF 先拆再传
- **MD 图片路径**：`marker-pdf`/MinerU 导出 md + json + 图片，路径要统一
- **Edit 工具无法匹配 HTML 注释**：拆脚手架时用 Python 脚本批量处理，不用 Edit 工具
- **并行 agent 误判并发修改**：多个 agent 同时改不同文件时，某 agent 可能误报"被并发进程修改"——实际是自己的多轮工作被误识别，grep 验证最终状态即可
